# One OK Studio 1.3.8

## Included changes

- Prompt editor: style library, complete asset-image selection, uploaded reference images, and unified Skill management.
- Square style previews preserve the whole image. Asset selection includes series, episodes, global assets and saved image versions.
- Identical Skills are deduplicated for selection while management preserves distinct versions.
- Development backend uses port 17178; installed builds use 17177.
- Local MiniMax input validation follows each model's reference-image limits. Gateway errors retain request diagnostics.

## Installer runtime

The Apple Silicon DMG targets macOS 11.1 and later (the bundled torchaudio C++ runtime requires 11.1). It includes the static frontend,
frozen Python backend, built-in Skills and model catalog, FFmpeg/FFprobe, an
on-demand Demucs runtime, and the local htdemucs checkpoint. Users supply their
own API key in Settings; no Python, Node, Rust or Homebrew installation is needed.

Runtime data remains outside the app under `~/.1okstudio/`. No user projects,
generated media, uploaded Skills, `.env` files or API keys enter the installer.

FFmpeg 8.0.3 and x264 commit `0480cb05fa188d37ae87e8f4fd8f1aea3711f7ee`
are built from upstream source with macOS deployment target 11.0 using
`scripts/build_release_ffmpeg_macos.sh`. The installer includes their source
archives, build instructions and GPL notices. Media preparation rejects binaries
missing the H.264/AAC encoders used by composition.

`runtime/release-manifest.json` and `runtime/python-requirements.lock` inside the
app record the actual build resources and Python dependency versions.

## Build

On the macOS build machine, prepare the pinned release Python environment and
the checksummed htdemucs checkpoint, then run:

```sh
bash scripts/build_release_ffmpeg_macos.sh
bash build_tauri_mac.sh
```

The release script signs the app, notarizes and staples both app and final DMG,
and checks Gatekeeper acceptance. Local packaged-runtime acceptance uses an
isolated data directory and system-only PATH. A separate physical machine
acceptance run remains necessary before broad distribution. Windows installers
must be built and accepted on Windows.
