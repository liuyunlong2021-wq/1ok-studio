## 1. 产品边界与已确定方向

风格是用户手动确认的最高制作准则。它先于工程剧本，约束导演设计、角色／场景／道具提示词和图片、声音表演、分段工程剧本及最终视频提示词。Skill 的默认竖屏、写实摄影或镜头配比不能覆盖用户已确认的风格；风格不授权改写原剧情事实或增删原台词。

用户在开始时手动确认：风格、画幅、视频模型／通道、对应提示词 Skill，以及单段最大总时长。风格可从系列继承，继承的是已确认版本；未确认或已修改的风格不能静默以默认值启动。确认一次后，正常执行不再逐步弹窗。

本期交付：用户确认风格与制作参数 → gongchengjuben 设计工程分镜 → 提取资产并复用 → 资产提示词和角色九维声音设计 → 生成资产图 → 分段工程剧本及结尾 1 秒全景 → H3／Seedance 视频提示词 → 逐段提交模型 → 接收并展示分段视频 → 按序拼接整集。

所有新输入统一经 gongchengjuben：普通文本、文学剧本、已有镜头文本都按已确认风格形成工程分镜；已有台本也不能未经核对风格直接绕过入口。同一已完成阶段的断点恢复允许复用检查点，不代表每次继续都再次调用 Skill。输入格式读取失败或内容为空先报错，不向模型发送不可读内容。

工程剧本本身就是导演设计完成的文字分镜，不再让另一套 AI 重新拆镜或改戏；不默认逐镜生成分镜图。角色仅生成并保存声音九维档案，不生成参考音、不调用 TTS，也不自动提交历史参考音。生成视频中的对白、环境音与动作音由所选视频通道承担。

全链路明确无 BGM：工程台本、分段包、模型提示词和最终合成都不生成、不叠加背景音乐；保留有依据的对白、环境声和动作音效。原输入若要求配乐，与本流程冲突，需在执行前明确处理，不能无声忽略冲突。

第一版采用固定 Python 步骤，在现有后端运行。一个后台执行器、逐项检查点、现有 JSON 持久化即可；暂不引入工作流平台、通用 DAG、Agent 自由规划、UI 点击脚本或新基础设施。

本期通过现有视频模型适配器逐段生成，复用 `video_tasks`、媒体下载和最终展示，但由本次运行的有序段清单决定合成输入；不接附件的云端长视频 ComfyUI 工作流。多集自动排队、资产并行生成、自动审美打分和自动挑最佳版本后续再做。

## 3. 用户流程与最小前端

1. 用户手动确认风格，并选择视频模型／通道、画幅、H3 或 Seedance 提示词 Skill、单段最大总时长。界面写明上限包含结尾 1 秒全景，例如「最多 27 秒＝剧情最多 26 秒＋结尾 1 秒」。
2. 在已有剧本编辑器粘贴本集内容，点击「自动执行」。启动前必须等待当前保存完成；后端核对原文版本、风格确认版本及制作参数。
3. 顶部轻量状态条展示阶段和数量，例如「生成资产图 · 3/7」，已有页面自然出现产物。
4. 逐段展示返回的视频；完成后展示「整集制作完成：7 个主体、18 个剧情镜头、6 段及整集成片」，新增全景镜头单独计数。
5. 出错定位到具体项，例如「第 3 段视频下载失败」，提供继续／重试入口及已有工作台链接。各段完成后自动拼接；缺段则保留分段展示并列出缺口。

状态条挂在 `ProjectClient`，切换剧本、Cast、分镜页面时仍可见。运行数据由后端保存；刷新页面只恢复展示，不再次发起运行。轮询对当前项目生效，切换项目时取消旧请求或忽略旧响应。

运行中支持「暂停」，显示“当前请求结束后暂停”；真正暂停后可修改资产或剧本。点击「继续」重新核对检查点。正常流程没有提取确认弹窗、台本确认弹窗或逐资产选版本要求。

模型和 Skill 使用现有设置能力，缺 Key、失效通道、未确认风格或不兼容的时长在预检阶段一次列清。Runtime 不为执行成功而静默换模型、放宽模型上限或替用户确认风格。

## 4. 固定执行顺序与完成条件

风格先决定工程分镜，工程分镜再决定资产范围。第一步使用已确认风格及系列已知名册，不提前生成资产；资产提取之后按主体绑定工程镜头，不再另做导演设计。

```text
用户手动确认风格、模型、Skill、画幅与段长上限
  → gongchengjuben 按风格设计工程分镜
  → 提取角色／场景／道具，匹配已有资产并绑定镜头
  → 生成各类资产提示词及角色声音九维档案
  → 生成场景／道具／角色资产图
  → 按段长预算分段，补结尾1秒全景，形成四部分分段工程剧本
  → 所选 H3／Seedance Skill 转写每段视频提示词
  → 提示词与对应资产图逐段提交视频模型
  → 下载并展示各段视频
  → 完整性检查，按本次运行段顺序拼接整集
```

第一版执行器串行处理单元。某个资产失败，先记录失败，再继续其他不依赖它的单元；最后汇总。无需为有限并行先增加调度复杂度。

| 阶段 | 输入与工作 | 完成条件 |
| --- | --- | --- |
| `screenplay` | 原始内容、已确认风格、gongchengjuben | 工程分镜体现风格及导演设计，通过解析器；时间轴从 00:00 开始且连续，原台词与动作节拍完整 |
| `extract` | 工程分镜、已知主体名册、主体提取 Skill | 返回可解析主体集合，完成唯一匹配／创建，并存下本集主体 ID 清单 |
| `storyboard` | 工程分镜、本集主体映射 | 同步工程镜头；场景和说话人唯一绑定、引用存在；不再次 AI 拆镜 |
| `asset_prompt` | 本集资产描述、类型、对应 Skill、风格和资产画幅 | 有可用提示词，记录描述版本与实际输入摘要；已有有效手动提示词直接复用 |
| `asset_image` | 当前提示词、模型与参数 | 当前选定图片可读取并解码；新生成仅一版，填入既有候选容器；不覆盖人工选择 |
| `voice_design` | 角色资料、形象提示词、本集对白、声音 Skill | 九维齐全并绑定稳定角色 ID；同一角色各段复用同一档案；无试听音频生成 |
| `segments` | 工程镜头、用户上限、模型能力、资产及声音档案 | 四部分分段包完整；剧情镜头覆盖无遗漏；每段恰有 1 秒结尾全景且总时长合法 |
| `video_prompt` | 本段工程剧本、实际图片、已确认风格、所选 Skill | 按模型格式转写，保留全部镜头／台词／九维／无 BGM／1 秒全景；图片编号对应提交清单 |
| `video` | 已验证视频提示词与有序资产图、模型参数 | 有且仅有本次目标请求的上游任务关联；完整视频下载到本地并通过时长与音视频流检查 |
| `assemble` | 本次运行所有成功段的有序清单 | 无缺段、无重复、参数兼容，拼接结果可播放；不混入历史 frame 候选或 BGM |

角色均有稳定九维文字身份，是否发声由本段工程剧本决定，无台词角色不能因档案存在而被模型强行加对白。旁白作为独立声音主体，不虚构图片编号或出镜形象；无人空镜不要求角色图。现有参考音保留，但不参与本次自动生产。

“制作完成”要求全部分段视频与整集文件已落地；它不表示通过自动审美验收。每段工程剧本和视频提示词在提交前可查看，用户暂停后可以返修。

## 5. 主体身份、跨集复用与写入范围

### 5.1 提取结果合并

Runtime 提取返回候选主体，随后在锁内按 ID／名称／别名与来源解析结果合并，不用 `reparse_project` 替换整个 `Script`。

- 同类型主体唯一命中已有 ID／名称／别名：沿用 ID 和角色身份；图片／描述／九维档案需与本次确认风格相容，不能把其他风格素材直接当成本次有效资产。
- 新主体：有系列时进入该系列资产池，独立项目进入本集资产池；把来源与 ID 记入本集清单。
- 已有本集私有造型优先于系列通用造型；新造型有明确区别时单独建资产，不覆盖通用形象。
- 同层多重命中或别名歧义：标记阻塞，指出候选；不能随便选一个。明确匹配优先级沿用既有解析约定。
- 当前文本没提及的既有资产保留；既有分镜、视频、段方案和运行状态不因提取被丢弃。
- 重试提取或提交恢复时，按已保存映射重新核对，不能再次创建同一主体。

只为本集提取清单及实际镜头引用中的主体准备素材，不遍历生成全局库。第一集新建的系列主体在第二集直接可复用，不依赖人工逐集提升资产。

### 5.2 已有资产和文件

已有符合本次确认风格的选定图片和声音九维档案优先复用。手动提示词、人工选择和锁定状态不被自动改写；不相容时显示具体项，保留原版本，创建本次独立造型或由用户处理后继续。当前通用生图方法尚未统一实施锁定保护，Runtime 入口必须检查。全局模板只读，不因风格切换被改写。

全局库只读复用；全局资产缺少本次所需产物时，复用既有 fork 语义，在系列／本集创建独立副本并重绑定本集映射，再生成；不静默修改所有项目共享的全局模板。

素材落在现有托管 `output/` 下，继续使用媒体引用工具。检查容器时兼容角色 `reference_sheet` 与旧 `full_body_asset`；后端取图顺序与 `characterImage.ts` 保持一致。生成新版本使用独立文件名，保留旧版，不在本期增加自动清理。

## 6. 原文、工程台本与分镜合同

原始剧本是来源，工程台本是派生产物。Runtime 保持 `Script.original_text` 为用户当前原文，生成台本放在已有 `Script.engineering_script.text`；运行记录另外保存启动时原文快照。

现状的 `engineering_status` 用工程台本 revision 与 `original_text` 对比，手动确认端点也会把台本文本写入 `original_text`。自动链路需增加来源绑定，不能直接反复调用确认端点：

1. Runtime 写入的 `engineering_script` 增加 `source_revision` 和 `style_revision`，分别绑定原文的 `screenplay_revision` 和用户确认风格版本；既有 `revision` 仍只代表台本文本。
2. `engineering_status` 对带 `source_revision` 的台本比对原文来源版本；旧台本缺该字段时保持原有判断。`storyboard_source_revision` 仍绑定台本 `revision`。
3. 所有新输入统一交给 gongchengjuben，按用户确认风格完成导演设计；已有合法台本要求保留事实／台词／已指定时间等约束，不擅自套默认风格。生成结果通过解析器后才进入资产提取与镜头绑定；不可再交给另一套 AI 拆镜。
4. 自动同步内部调用同一套 preview／token 校验与 apply；保留已有分镜存档和稳定 ID 规则。依赖旧正文等于台本的调用方要一并覆盖，不能仅改状态显示。
5. 新分镜／变更分镜在主体绑定、时间码和数据校验通过后，才能标记本次已检查；有歧义或未知说话人时保留阻塞，不直接清空 `review_required`。

原文编辑器与其文档保存格式不被 Runtime 覆写。派生台本通过分镜和运行结果查看；现有工程台本工作台需要读取派生文本的地方复用该字段，不把生成内容写回 TipTap 文档冒充用户原文。

台本生成复用既有 Skill 编译与文本适配器。系统规则中先放用户确认风格及本流程合同，再放对应 Skill；原文放用户消息。Skill 默认值不能覆盖风格确认，无 BGM、每段末尾全景等用户明确规则覆盖 Skill 默认配比。原内容不能变成执行器指令。固定项目使用的 Skill 版本，避免本机同名 Skill 与项目打包版不同造成结果漂移。

## 7. 最小数据合同

在 `Script` 增加一个可选的 `preparation_run`，旧项目默认为 `None`。第一版只保存最近一次运行，不增加独立任务数据库和无限运行历史。

```text
PreparationRun
  id, request_id, recipe_version = 2
  status: queued | running | pausing | paused | blocked | failed | stale | completed
  source_text, source_hash                    # 本次不可变原文快照
  settings_snapshot, settings_hash            # 已解析配置，绝不含 Key
  style_revision, style_confirmed_at          # 用户手动确认；不由 worker 代填
  max_segment_seconds, tail_seconds = 1       # 总时长上限含结尾全景
  video_prompt_skill, video_model             # Skill 与实际视频通道分别保存
  assets: [{kind, asset_id, owner_kind, owner_id}]
  units: [PreparationUnit]
  created_at, updated_at, finished_at?, error?

PreparationUnit
  key                                        # 如 image:character:<id>
  stage, target_id?
  status: pending | running | completed | reused | failed | blocked | uncertain | stale
  input_hash, attempts
  output_refs                                # 资产版本 ID、镜头 ID 或段输入
  provider_name?, provider_task_id?           # 仅真实返回可查询任务号时填写
  request_started_at?, finished_at?, error?
```

沿用首稿 `PreparationRun`／`preparation_run` 的技术命名，覆盖范围已扩至最终制作；这些仍是待实现数据结构，不是已存在接口。`settings_snapshot` 保存文本／图像／视频模型及通道、已确认风格全文、各资产画幅、视频画幅、段长上限、无 BGM 约定及编译后的 Skill 文本和摘要；本流程没有独立音频模型生成阶段。

启动解析一次，内部函数接收明确的有效配置；现有会在执行时重新读取全局模型／Skill 的方法需允许传入本次配置。不能一边声称配置已冻结，一边让后续角色读到用户刚换的模型。

段级输出存到 `segments` 单元的 `output_refs` 中，每段包含：

```text
index, source_frame_ids, source_revision
story_seconds, tail_seconds = 1, total_seconds, ratio
synopsis                                      # 第1部分：一句话分段简介
asset_manifest                                # 第2部分：角色／场景／道具
confirmed_style, style_revision, bgm = none    # 第3部分：确认风格全文
local_shots                                   # 第4部分：本段局部时间轴
entry_state, exit_state                       # 内部空间继承数据，渲染在第4部分
segment_script_text, video_prompt, prompt_skill
video_task_id?, video_variant_id?, video_url?
```

素材清单含稳定主体 ID、实际图片编号、所选图片版本 ID 及媒体引用；角色带声音九维档案，场景和道具带从其资产提示词摘取的短描述。旁白只保留声音身份，不伪造图片。视频单元关联既有 `VideoTask`；同一段重试保留历史候选，本次采用版本由运行清单明确记录。

每个 `input_hash` 只覆盖该单元实际消费的输入，例如图片依赖描述／提示词版本、风格、图片模型与资产画幅；不能把整集总配置 hash 当成每个单元唯一缓存键，否则改分段长度也会重新生图。

历史手动产物没有 Runtime hash 时，只要选定产物有效、没有已知过期信息就可标为 `reused`，记录当前版本引用。已知过期产物与本次新生成结果分开处理，不能仅凭 URL 非空判断有效。

## 8. 执行器、写盘与恢复

### 8.1 执行方式

新增 `episode_preparation.py` 承载固定步骤和状态转换；API 只负责校验、启动与读取。一个受生命周期管理的后台 worker 从已落盘的运行记录获取工作；队列唤醒信号可在内存，但任务事实必须在磁盘。

第一版一个后端进程、一个 Runtime 执行槽。同一项目已有活动运行时返回原运行；另一个项目启动时返回 `409 RUNTIME_BUSY`，不增加隐藏的多集队列。前端不驱动步骤，worker 不调用自己的 HTTP 端点。

worker 在每个单元前检查暂停、输入版本、风格确认版本与依赖；短锁内读写，模型网络调用期间不持有 `_save_lock`。运行对本项目及将写入的系列资产声明占用；相关手动写入／生成入口在执行中返回 `409 PREPARATION_BUSY`，暂停真正生效后解除。只读访问和无关项目操作正常。

已有手动生成未结束时，预检返回涉及的资产和任务，不再启动第二份。所有会修改占用资源的提取、描述、选图选音、绑定、台本同步及删除入口都需检查，不能只禁用一个前端按钮。

### 8.2 每个外部调用的提交顺序

1. 保存单元输入摘要、目标输出位置与 `running` 状态；写盘成功才允许调用模型。
2. 计算／调用生成；已有函数将计算与写回混在一起的，抽出最小内部提交边界，使提交前可复查版本。
3. 验证返回产物及输入版本，保留文件和候选；不得把旧请求结果覆盖到新版本输入上。
4. 在同一检查点中保存资产引用及单元完成状态。跨系列／项目两份 JSON 时先保存产物所属资产池，再保存项目检查点。
5. 后一步写盘失败立即停 worker；恢复时核对已保存的产物版本引用，不依赖内存中的“已完成”。

Runtime 使用严格写盘：为现有持久化方法增加默认兼容的严格模式，或抽出共享的抛错保存函数。磁盘满、权限失败等必须向上传播，不能记录日志后继续发起付费请求。

跨两个 JSON 文件不声称事务原子性。新版本文件名／ID 在外部请求前记录于单元，恢复按它们寻找产物；系列产物已保存但项目检查点未更新时可重新关联，不能再次生一版。

### 8.3 暂停、失败和重启

正常状态转换为 `queued → running → completed`；暂停为 `running → pausing → paused`，继续为 `paused → queued`。单元失败汇总为 `blocked`，全局错误为 `failed`；排除原因后通过继续／指定项重试回到 `queued`。输入来源变化转 `stale`，只能启动新运行；`completed` 和 `stale` 不直接通过 resume 重新生成。控制 API 与 worker 共用这一套转换规则。

| 情况 | 处理 |
| --- | --- |
| 刷新／切页／关闭浏览器 | 后端还活着就继续；重新打开按项目读取状态 |
| 桌面 App 退出，连同 sidecar 停止 | 执行会停止；下次启动恢复记录，不承诺退出后仍运行 |
| 请求暂停 | 状态改为 `pausing`；当前外部请求结束并完成检查点后转 `paused`，不发起下一个请求 |
| 单个资产／段明确失败 | 记录 `failed`；其他独立项继续；依赖它的项标 `blocked`；缺段不合成整集，最终运行 `blocked` |
| 鉴权／配置／持久化错误 | 停止整个运行，`failed` 并给出可操作原因 |
| 后端重启 | 在 worker 启动前扫描：未结束运行转 `paused`，进行中单元逐项对账 |
| 对账找到完整产物 | 验证输入和文件，标为完成；继续时跳过 |
| 请求可能已发送但无任务号／产物 | 标 `uncertain`；普通“继续”不重发，只能用户明确选中该项重新生成 |
| 返回有效上游任务号 | 保存并按同一号查询／下载；只有该通道真实支持时启用，不能假设图片音频都有任务号 |

图像与部分文本请求同步返回，视频任务通常有上游号。拿到视频号立即保存，重启／超时后先查询或下载原任务，不重新生成；同时协调现有 `_recover_orphan_tasks`，避免其先把 Runtime 的活动视频错误地当作需重发的失败任务。上游已接收但创建响应丢失时仍可能无法保证 exactly-once，必须标待核实。

暂停不会取消已经提交的上游视频任务。可保存任务号后暂停等待，恢复时先对账；不能把“本地取消轮询”解释成“上游停止收费”。下载失败只重试下载；合成失败只重试合成。

只读查询／下载可有限重试。Runtime 不叠加一层盲目重试付费请求；已有文本生成重试沿用其边界。明确失败项由用户点击重试后重新生成，不增加正常流程的逐步审批。

## 9. 继续执行与局部失效

恢复时先确认当前原文和本次来源一致；不一致则旧运行标 `stale`，重新启动基于新原文的运行。新运行替换最近运行记录前，保留其有效单元检查点用于本次复用，不清理既有媒体与资产。

配置变化也创建新运行，重新解析配置；旧运行不能静默切模型。由逐单元 hash 和产物检查决定哪些可以继续使用。

| 变化 | 最小受影响范围 |
| --- | --- |
| 风格改动并由用户重新确认 | 工程台本及全部消费该风格的自动产物、分段提示词与视频过期；保留旧文件和稳定主体 ID，不用新风格偷偷续旧运行 |
| 角色视觉描述／视觉 Skill／资产画幅 | 该角色图提示词与图；形象信息实际改变时更新相关声音提示词；重建引用该角色的段输入 |
| 角色声音九维档案 | 引用该角色的分段包、视频提示词及相关视频；不生成参考音，角色图和镜头时长不失效 |
| 选另一版图片 | 重建有关段的素材引用与对应提示词；保留旧视频，不自动覆盖人工采用的版本 |
| 图片模型 | 本次尚需生成／明确更新的图片；手动选定或已明确复用的素材不自动换版 |
| 画幅／段长上限／下游视频模型或提示词 Skill | 重排必要分段、全景和提示词，相关视频与合成过期；不重新提取所有主体 |
| 原文／镜头时长与顺序 | 重算派生台本／分镜和段方案；稳定身份资产尽可能复用 |

人工修改后的版本优先。继续是补齐缺失或明确过期的自动产物，不等于覆盖所有资产；需要替换人工结果时在已有工作台明确操作。

## 10. 分段工程剧本、模型提示词与成片合同

### 10.1 段长由用户在开始时选择

`max_segment_seconds` 是整段输出上限，包含最后 1 秒全景。按本次要求，H3 路线可选至 27 秒，Seedance 路线可选至 29 秒；用户也可选更短上限。该上限不是每段必须填满的固定长度。

| 用户选择的最大总时长 | 剧情可用时长 | 结尾全景 |
| --- | --- | --- |
| 12 秒 | 最多 11 秒 | 1 秒 |
| H3 27 秒 | 最多 26 秒 | 1 秒 |
| Seedance 29 秒 | 最多 28 秒 | 1 秒 |

计算：`story_budget = max_segment_seconds - 1`，`total_seconds = sum(source_shot_seconds) + 1 <= max_segment_seconds`。末段同样包含 1 秒全景，不为凑满上限填无意义停顿。段总时长必须同时落在实际通道支持的时长集合内；最小长度不足时重新分配邻段镜头，不能擅增对白或改变语速。

按完整镜头和剧情自然落点分段，换场优先作为边界，不把两个空间的人物拉进同一个结尾全景。单镜超剧情预算时在工程台本阶段按自然对白／动作节点拆镜并复核，不能机械截断；无法保留原内容则定位阻塞。

复用 `Segment.frame_ids`、`manual` 等已有概念，但区分原剧情时长和新增全景时长。原工程镜头保持可追溯；分段版本记录局部时间、来源镜头 ID 和新增尾镜 ID，不把新增尾镜反写原稿，重复分段也不重复插镜。手动锚点重新验证连续、无重复、预算有效。

原 `duration_bounds` 的 `int` 截断和 min/max 粗化需修正为实际通道的 step／枚举约束；显式更改上限必须重排，不能因 `ensure_segments` 认为旧镜头没变而复用旧方案。

### 10.2 每段固定四部分

对用户可见的分段工程剧本严格只有以下四部分。位置关系写入第四部分的开场承接和结尾镜头；内部仍保存 `entry_state / exit_state`，不额外增加第五个“位置关系”章节。

```text
一、分段简介
分段简介：甲愤怒地咒骂他的妻子乙，乙默默承受。

二、参考资产
角色：甲，对应图片{n}；声音九维：{完整九维档案}。
角色：乙，对应图片{m}；声音九维：{完整九维档案}。
场景：{场景名}，对应图片{k}；{从场景资产提示词摘取的简单描述}。
道具：{道具名}，对应图片{j}；{从道具资产提示词摘取的简单描述}。

三、确认风格
{用户已确认的风格正文，包括已选光影、摄影机型号与镜头语言等约定}。
无 BGM；保留本段工程剧本明确安排的对白、环境声和动作音效。

四、本段工程剧本
开场承接：{上段结束的实际站位、观察侧、朝向、距离、视线和持物状态}。
镜头一【00:00-00:xx】
{按确认风格设计的剧情镜头规格、表演与原台词}。
……
镜头末【00:tt-00:tt+1】
【双人全景，{同一观察侧的稳定机位}，{与风格相符的构图}】
{在场两人的实际位置、前后距离、朝向、视线、持物、地标和自然余势}。
```

此处花括号为模板占位，不是实际图号或可提交模型的时间码；最终产物必须替换为真实编号和合法 `MM:SS` 时间。简介只用一句话表达“主体＋人物关系＋情绪＋内容概述”，不新增剧情、旁白台词或单独的生成镜头。

角色声音九维固定为年龄感、音高、明暗、厚薄、共鸣、气息、颗粒感、口音、稳定表达习惯；单句情绪写在工程表演中，不改九维身份。每段完整重复本段角色档案，不写“同上”；无语言发声的角色标注不适用项，不能为满足字段凭空加人声。场景／道具短描述摘取已定提示词中的身份和视觉锚点，不新做一轮风格设计。

参考资产只包含本段实际使用对象，包含末尾全景中出现的主体。展示按角色 → 场景 → 道具分组，图片编号与实际上传清单一一对应；为复用当前逻辑，实际编号继续按镜头中首次出现收集，同镜按场景 → 角色 → 道具排序，展示分组不再重编号。旁白没有角色图片时明确标“画外声音，无参考图”，不能占用虚构图号。

### 10.3 最后 1 秒全景与跨段空间

每段恰有一镜 1 秒空间交代：一人为单人全景，两人为双人全景，三人为三人全景，多人为交代核心角色及群体层次的全景，无人为环境空镜。人数取该时刻仍在同一场景中的人，不是本段曾出现过的全部角色；离场、隔墙和不同地点人物不能被召回凑同框。

在正文的安全动作落点切入尾镜，保留呼吸和动作余势，不冻结、不新增对白和剧情事件。尾镜直接展示已有站位，不要求摄影机在 1 秒内完成复杂后拉或重新排人。写清地标、实际左右前后、距离、朝向、视线、持物及观察侧；下一段 `entry_state` 必须直接继承该 `exit_state`，不让 LLM 独立猜一份新站位。明确换场时单独建立新空间。

每段末尾统一新增这一秒，即使原剧情最后一镜也是全景，也从它的结束状态继续 1 秒，而不是重复播放已经发生的动作。整集计划时长等于剧情原时长加段数秒。段时间轴按新增尾镜重算，原稿时间码作为来源保留；重复规划同一版本时先重建派生镜头，不能累计追加尾镜。

该规则按用户要求覆盖 gongchengjuben 默认“全片全景仅少量”的配比；工程台本对原剧情的镜头设计仍按确认风格，尾镜属于本次分段规则。

### 10.4 风格与无 BGM 的继承

各段第三部分复制同一个已确认风格版本，不再次让 LLM 重新总结或自由补摄影机型号。风格未指定的摄影参数若需要明确，应在开头风格确认时补齐后统一冻结。同场光影方向和曝光连续；剧情明确日夜／内外换场时按工程台本的物理光源变化执行，不把统一风格理解为所有地点使用同一个光源。

九维声音属于文本生成指导，不声称它能像真实参考音一样锁定音色。无 BGM 是独立硬约定：H3 的 `non_diegetic_music` 写 `N/A`，Seedance 在支持的结构中明确无背景配乐；不得把片段简介念成旁白，不能把环境音误删成全片静音。

### 10.5 H3／Seedance Skill 负责忠实转写

最终视频提示词必须经用户选定的 Skill，输入为四部分分段包、实际参考图和总时长；保留原镜头顺序、全部对白、声音九维、已确认风格及尾镜，不再次改变剧情设计。参考编号、说话人、总时长、最后 1 秒和无 BGM 是提交前的硬校验。模型参数单独由适配器提交，不能只把时长写在提示词里。

H3 与 Seedance 分别保存模板／executor ID 和版本；不是仅更换显示名。H3 参考生视频按其真实参考标签组织；无参考音时不出现虚构 `<Audio N>`。Seedance 选择适合工程台本文字转写的技能；依赖卷轴图的 `jc-seedance-fenjing` 不能在本流程缺卷轴时伪装成已具备输入。

项目内 H3 Context IR 当前本地请求校验只允许 4–15 秒，本机 H3 文本 Skill 也有默认短片段时长；本轮未验证云端 IR 的长段能力。27 秒路线必须使用明确支持该合同的项目版文本转写模板／executor，并验证生成通道；不能只删除本地校验就声称云端支持。用户的新段长要求覆盖本地模板的默认时长，但不能覆盖真实接口限制。

实际通道能力在预检读取：H3 Ref2V 当前目录存在 1–28 秒路线及较短路线；Seedance 同时有固定 30 秒和 4–30 秒等路线。29 秒上限只能选择支持相应时长的通道；固定 30 秒路线不能假装提交 29 秒，也不能默认裁掉 1 秒来凑合。目录标记与真实返回都要验证，本轮不修改模型目录。

### 10.6 视频接收、展示与拼接

每段关联一个本次采用的 `VideoTask`，保存源镜头 ID、分段版本、含尾镜总时长和上游任务号。现有 `create_video_task` 会根据 `source_frame_ids` 把时长重算为原镜头之和；Runtime 需要受校验的分段快照入口，将尾镜纳入计算，不能沿用旧路径丢掉这一秒或修改旧单镜手动行为。

不触发 `process_video_task` 中独立 Seed Audio 前置生成：本流程传 `generate_audio=False`、无 `audio_url`、无参考音列表；这只关闭应用额外生音步骤，不等同于要求视频模型输出静音。所选通道需真实支持本段所需同期对白／音效，否则预检阻塞，不能用 TTS 默默兜底。支持的原生声音开关由该通道既有合同明确提交。

接收一段即下载、验证视频流／音频流与实际时长，展示到对应段。时长容差按请求 fps 的帧粒度校验，超出容差记录可读原因，不能静默裁对白或全景。模型声称完成但产物未落地不算单元完成。

合成仅按本次运行的段序及明确采用的 task ID 收集一次；不按每个原镜头重复加整段视频，也不自动选历史首个成功候选。全部段成功且输入版本一致才拼接；缺段、文件缺失、参数不兼容都列明原因。必要时仅转码统一编码／分辨率／fps，不改变段内容与播放速度。

调用严格合成入口，显式禁用现有 `_maybe_apply_bgm_mux` 及项目遗留 `bgm_url`；不改动项目原设置。最终写入新的 `merged_video_url`，保留既有成片。默认硬切，保留结尾全景 1 秒，不额外叠化消耗时长。只有全部段与最终文件有效，运行才为 `completed`。

## 11. API 合同

端点名称为本设计新增；保留现有手动接口。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /projects/{id}/preparation-runs` | 校验预期原文版本，冻结配置，创建并持久化运行，然后唤醒 worker；返回 `202` 和运行摘要 |
| `GET /projects/{id}/preparation-runs/current` | 返回当前运行及逐项状态；没有运行返回 `200`，`run: null` |
| `POST /projects/{id}/preparation-runs/{run_id}/pause` | 请求暂停；已暂停时幂等 |
| `POST /projects/{id}/preparation-runs/{run_id}/resume` | 核对输入、对账并继续；不重新提交 `uncertain` 项 |
| `POST /projects/{id}/preparation-runs/{run_id}/retry` | body 为明确的 `unit_keys`，重跑指定失败／待核实项和必要下游，已有独立成果复用 |

启动 body：`{request_id, expected_source_hash, expected_style_revision, expected_settings_hash, expected_previous_run_id}`，首次的 `expected_previous_run_id` 为 `null`。原文和用户确认的风格／制作设置先由保存接口落地，服务端核对确认版本后冻结；重放当前运行的同一 `request_id` 返回该运行。同项目已有运行时返回已有运行，内容或配置不一致返回 `409`；已完成且输入未变返回现有完成结果。并发启动检查和持久化在同一短锁内完成。

风格确认复用现有 ArtDirection 保存流程，增加用户明确确认的版本与时间；点击普通保存不等于后台替用户确认。制作设置含 `max_segment_seconds / video_model / video_prompt_skill / ratio`，界面只展示该组合支持的段长。当前接口若缺这些字段，按现有设置端点最小扩展，不把风格正文和 Key 随每次控制请求反复传输。

创建新运行还需比对客户端预期的上一运行 ID。第一版只保留最近运行，因此旧请求在运行已替换后返回 `409`，不能因找不到旧 `request_id` 又创建一次付费流程；本期不提供任意历史请求回放查询。

重试 body：`{unit_keys: ["video:segment:<index>"]}`。仅允许当前运行的可重试项，不能让客户端指定任意业务函数或文件路径。视频任务有上游号时先回捞，下载／合成失败仅重跑对应操作。对 `uncertain` 项，这个显式操作代表允许重新生成，界面在该项旁说明可能再次产生费用。

控制端点先验证 `{project_id, run_id}` 关联。运行已被新版本替换时，旧控制请求返回 `409`；不存在项目返回 `404`，输入缺失或能力不匹配返回 `422`。读接口不做自动重排、不发起生成。

项目读取继续返回原有资产与分镜。运行摘要用于进度；产物变化后通过既有项目 GET 更新 store，保留 `original_text → originalText` 映射。前端不得把旧轮询覆盖到新项目或编辑器未保存草稿。

## 14. 与旧方案的关系及交付标准

`docs/10-episode-batch-render/2026-10-07-episode-auto-segmentation-plan.md` 中已实现的 Segment 和文字继承继续复用；队列和合成改由本期全链路 Runtime 统一驱动，不另建一套互相竞争的整集 Job。附件中的云端 H3 工作流仍不进入本期依赖。

本设计的完成标准是：用户手动确认风格与制作参数后，每集保存剧本、点击一次自动执行，得到分段视频和整集成片；期间无需依次点击台本设计、资产提取、提示词、生图、九维设计、分段、转写、逐段生成和拼接。每段按固定四部分组织，最后 1 秒为全景，模型和合成都无 BGM；异常可定位、可继续，已有成果保留。

第一版限制：后端单进程、Runtime 单任务串行；退出 sidecar 后停止；同步付费接口中断后可能需要核实；没有审美自动打分和自动挑最佳版本。限制要在对应代码中按 `shortcut: <限制>, <升级时机>` 标记，部署为多 worker 或引入并行时再升级跨进程调度与存储。
