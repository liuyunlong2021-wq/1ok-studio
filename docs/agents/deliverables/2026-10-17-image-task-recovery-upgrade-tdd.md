# 图片任务与产物回捞升级 · TDD

日期：2026-10-17
状态：A 阶段软件端已在本地工作树实现；B 阶段待 NewAPI 宿主异步图片合同确认。未部署，也未完成真实付费／重启验收。

适用：One OK Studio 的第三步资产图片生成，覆盖角色及其多造型、场景、道具；保持现有六步流程。通用下载能力应可供 Playground 复用，但本期不扩展成通用工作流引擎。

## 1. 目标与完成标准

用户已经付费生成的图片，不应因短暂断网、下载失败、页面关闭或软件重启而失去获取路径。生成请求结果不明时，不自动重复生成。

完成需同时满足：

1. 提交、查询、下载、资产入库分阶段记录，错误能定位到阶段。
2. 一旦取得上游任务号或产物地址，先持久化，再进入下一阶段。
3. “继续取回”只查询原任务或下载原产物，不调用生成 POST、不产生新的生成任务。
4. 任务与下载恢复后，图片回到原项目、原资产、原造型；不能串图、覆盖人工主图或采用过期结果。
5. 插件全异步链路部署后，客户端不再依赖贯穿整个 ComfyUI 生成过程的 HTTP 长连接。
6. 软件和适配器重启后任务仍可追踪；真实断网、重启小样通过后才能声明完整验收完成。

网络永久故障、文件实际损坏或已超过保留期不能承诺必然恢复；必须保留明确错误和可核对编号。

## 3. 最小实施边界

分两阶段交付；第一阶段可独立降低损失，但不能宣称解决长请求响应丢失。

### A：软件端产物回捞

- 沿用现有同步图片接口，拿到结果后立刻保存 URL／产物描述。
- 实现下载补偿、媒体校验和安全入库。
- 原资产工作台、批量任务显示中增加状态及“继续取回”，不新增制作步骤、设置页或下载中心。
- 覆盖已拿到 URL 的任务；没有 URL／上游任务号的历史请求仍只能核对后台。

### B：端到端异步与幂等

- 修改适配器、插件／NewAPI 对外合同、软件调用方。
- 短请求取得任务号，随后查询、下载；完整支持重启恢复及重复提交去重。
- 为已生成文件提供独立、可恢复的存储与下载入口。

本期不引入 Redis、Celery、消息队列、断点 Range 下载、跨供应商自动切换或自动补生成。图片体积小，有界全量 GET 重试足够。优先使用现有项目 JSON 存储；适配器如无可复用持久层，使用标准库 SQLite。

## 4. 任务合同与状态

扩展现有资产图片任务记录；字段名以实现时统一模型为准，以下为语义合同，不要求同时维护多份等价字段。

| 字段 | 含义 |
| --- | --- |
| `task_id`、项目／资产类型／资产 ID／`look_id` | 软件任务及不可变目标，旧无造型资产允许 look_id 为空 |
| `client_request_id` | 生成意图的稳定唯一标识；网络恢复沿用，用户明确重新生成才创建新标识 |
| `provider_task_id`、`provider_request_id` | 上游任务号及排障请求号；两者不可互相冒充 |
| `phase` | 下表阶段，是本期细分状态的唯一事实来源 |
| `provider_status` | 上游最后一次确认的状态，可空；本地断网不得把它改成上游失败 |
| `artifacts[]` | 产物 ID、受控下载位置、MIME、可得的字节数／摘要、过期信息、本地路径及下载尝试记录 |
| 现有版本快照 | 人物身份／造型描述版本、提示词、风格／制作设置／工程剧本版本 |
| 错误、创建／开始／结束时间 | 记录阶段、错误类别、脱敏摘要和编号 |

`status` 为兼容旧客户端保留 pending／processing／completed／failed 投影；不能由它反推是否应重新生成。新客户端的操作按钮按 phase 和能力判断。

| phase | 语义 | 允许操作 |
| --- | --- | --- |
| `queued` | 本地已持久化、尚未开始提交 | 执行首次提交 |
| `submitting` | 已开始发送，尚未确认是否受理 | 不并发提交第二次 |
| `unconfirmed` | 提交结果不明 | 按 client_request_id 对账；无查询能力则人工核对 |
| `generating` | 已有上游任务号，等待生成 | 查询同一任务 |
| `downloading` | 上游成功、结果已保存，取回文件 | 下载已有产物 |
| `download_pending` | 下载重试耗尽／暂时中断 | 继续取回，不重新生成 |
| `completed` | 文件验证、入库、持久化均成功 | 正常使用 |
| `failed` | 明确的上游终态失败或不可恢复错误 | 显示原因；重新生成需用户明确操作 |
| `expired` | 确认文件已删除／保留期结束 | 不假装可回捞；由用户决定是否重新生成 |

另记录采用结果（已采用／候选／因版本过期未采用），不把“未自动采用”误报为“生成失败”。

任务历史不能被下一次生成整体覆盖：沿用项目内持久化列表或现有任务存储，资产上的当前任务字段仅指向活动记录。候选与历史任务保留关联，限制增长时必须先定义可见保留策略，不静默删除待回捞记录。

## 5. 软件端执行与恢复

1. 提交前先保存任务及 client_request_id；写盘失败立即停止，不发计费请求。
2. 上游任务号返回后先写盘，再开始轮询。写盘失败不得偷偷新建生成任务。
3. 上游成功或同步响应有产物时，先保存 artifacts，再启动下载。Base64 结果直接走受限解码和同一文件校验，不存进任务 JSON。
4. 图片 GET 有界重试：初始方案最多 3 次，退避 2／5 秒；使用连接和读取超时，处理中断流时从头重取。重试 429、500、502、503、504、520、522、524 及暂时性连接／读取错误；429 优先遵守有界 Retry-After。
5. 401／403 不无限重试、不通过关 TLS 或改代理绕过。签名 URL 过期且支持刷新时，查询原任务取得新地址；无法刷新则显示原因。单次 404 不直接推断永久过期，以任务接口／保留策略为准。
6. 下载先写目标目录下独立临时文件；检查大小上限、非空、可用的 Content-Length（注意编码语义），用 Pillow 实际解码校验，存在可信摘要则验证。不是 PNG 的内容不得仅改扩展名伪装 PNG；沿用正确类型或规范化保存。
7. 校验后原子替换到确定的产物路径，再写资产候选及完成状态。同一 artifact 重放不重复插入候选；文件已落盘但状态未提交的中断，由恢复流程校验文件并补提交。
8. 版本过期、资产锁定或主图已被用户选择：只保留可见候选／历史结果，不覆盖主图，不串到另一套造型。资产被删除则保留任务诊断，不自动重建资产。
9. 保持现有首图采用策略；只有实际采用图变化才使相关分段过期。下载重试、收藏或单纯增加候选不使已确认分段失效。
10. 批量中一个任务失败不丢弃其他成功候选；显示每个目标状态和成功／待取回／失败数量。遇到提交结果不明时停止新的自动批量提交，避免连买多张无法确认的产物。

启动时不触发新生成：queued 可恢复首次执行；submitting 转 unconfirmed 并对账；有 task ID 的任务恢复查询；有 artifacts 的任务恢复下载；completed 校验本地引用。重复启动恢复或多次点击继续，按 task_id 去重，只允许运行一个回捞执行器。

## 6. 适配器、插件与网关升级

### 6.1 发布前合同检查（强制门槛）

核对生产 NewAPI 版本、插件 API 限制、openai_image 宿主行为和鉴权下载协议，并用现有契约测试验证。不能仅让插件向适配器异步提交、却让 NewAPI 对客户端继续等待最终图片；这仍会保留外层超时问题。

若现版本只提供同步 OpenAI 图片响应，需要增加／使用独立的可查询图片任务入口，或升级宿主。具体公网路由以验证后的宿主能力确定，不在设计中假称某个 `/v1/images/tasks` 已可用。客户端按明确能力切换，未知路由不自动降级为第二次计费提交。

### 6.2 服务端语义合同

- submit：短请求接收 client_request_id，先持久化任务再返回稳定的公开 task ID；队列等待不占用生成长连接。宿主内部响应码遵守当前适配器／NewAPI 合同，不能因“习惯返回 202”造成宿主误判。
- query：按公开 task ID 或 client_request_id 查询；返回状态、脱敏错误和产物描述，不重新执行工作流。
- content：按 task ID＋artifact ID 鉴权获取文件；不能把内网 `frps:8796` 暴露给客户端，不用任意 URL 代理替代产物授权。
- 幂等：以账号／租户＋模型通道＋client_request_id 建唯一约束，保存规范化请求摘要。相同键与摘要返回原任务；相同键不同内容拒绝冲突。并发重复请求也只能创建一个执行任务。
- 计费与执行关联同一逻辑任务，重复提交、查询、补下载不重新结算生成费用。需要验证 NewAPI 与适配器两层，不能只有适配器去重而网关扣两次。
- 提交 ComfyUI 也存在“已受理但本机没保存 prompt_id”的窗口。请求标识需可随提交元数据追踪，并结合队列／history 对账；无法证明未受理时保持 unconfirmed，不盲目重投工作流。
- 适配器重启后读取持久化任务，按 Comfy prompt_id／请求标识查询队列和 history，区分仍执行、已成功及确实失败；记录实际本地输出文件名和每张产物，不把所有任务一律重跑。

### 6.3 产物可靠存储

推荐复用现有 VPS／对象存储能力：Comfy 成功后将产物可靠转存，验证大小／可用摘要，通过后发布“产物就绪”。这样软件下载不必每次重新穿过本机隧道。

转存失败只重试搬运原文件，不再生成；可暴露“生成成功、产物转存中”。若第一阶段暂时仍走 `/files/`，必须明确它依赖隧道，不能将这阶段标记为存储可靠性已完成。

定义并对外返回任务／文件保留期限；下载待恢复期间不得因短时自动清理悄悄删除。清理采用现有产品保留策略，超期记录明确 expired，不承诺永久保留，也不无限占用本机磁盘。

## 7. 软件 API 与界面合同

以下软件 API 为拟新增，不代表已实现：

- `POST /projects/{script_id}/asset_tasks/{task_id}/resume`：仅恢复已有任务。无任务号、无产物地址且无幂等查询能力时返回可读的冲突错误，不能隐式新建生成。
- 继续复用 `GET /tasks/{task_id}`，补 phase、目标造型、错误阶段及可恢复能力；不向普通响应回传上游密钥。
- 原 `assets/generate` 保持创建新生成意图；既有调用兼容。重复点按由服务器原子去重，不能仅依赖前端按钮禁用。
- “重新生成”与“继续取回”明确区分：前者提示可能再次计费、创建新请求标识；后者保证不提交新生成。
- 工作台和现有批量区显示“等待生成”“结果待确认”“已生成，下载中”“已生成，待取回”“已完成／候选”“已过期”。下载失败不能只显示泛化的“生成失败”。
- 刷新项目、关闭弹窗、切造型和软件重启后，依据持久任务恢复显示与轮询；目标键包含项目／资产／look，沿用现有复合键。

不增加模型选择或下载配置要求，不改变第一步制作设置，也不要求用户上传 Skill。

## 8. 安全与一致性

- TLS 验证保持开启；不照搬源站 verify=False。
- 仅接受服务端验证过的产物位置；限制下载协议、允许域名／路径、重定向次数，阻止回环／私网／元数据地址等 SSRF。内部下载代理只按授权的 artifact ID 找文件。
- 下载外部签名 URL 不携带网关 Authorization；认证只发给明确受信任的网关接口，重定向不得泄露凭据。
- 签名地址按现有私有运行时数据策略保存，不进 Git、日志、普通诊断响应；日志保留去敏错误码、task ID、request ID。
- 下载大小设上限，不将 HTML 错误页当图片。临时文件路径与目标路径由服务端生成，拒绝路径穿越；部分失败清理临时文件，保留旧正式文件。
- 数据写盘用现有严格保存／原子替换；并发任务完成不能覆盖用户期间的描述、主图和另一造型的任务。
- 一个逻辑任务支持多个产物、部分取回和重放，不能因仅消费 `data[0]` 丢掉已付费的其他图片。

## 9. 历史任务迁移与本次成品回捞

1. 旧字段默认兼容，升级不得清空媒体或要求用户重建项目。
2. 有结构化产物地址／上游任务号：迁移后可继续取回。
3. 本次塞莉丝地址仅出现在错误文本中，可提供一次人工确认的修复流程：核对项目／资产／提示词与时间、验证地址受信任后附加为恢复描述，再补下载；不在每次启动时从任意错误字符串自动抓 URL。
4. 无编号、无地址的历史任务：需要从用户已授权的后台确认并映射产物；不得按名字／最近图片猜测绑定，不声称能凭空恢复。
5. 如果后台源文件仍在但临时 URL 失效，按原任务重新发布下载位置；不重新运行生成工作流。

## 11. 测试驱动验收

先写失败测试，再实施。默认 mock 网关，不调用付费模型。

| 编号 | 场景 | 必须满足 |

## 12. 实施顺序与发布

1. 软件下载补偿：先测结果持久化、原 URL GET 重试、文件校验和原位继续取回；可独立发布 A。
2. 核对 NewAPI 宿主能力，锁定短提交／query／content 和计费合同，先写契约测试。
3. 适配器任务持久化、幂等、Comfy 对账；插件图片异步与产物代理；可靠存储联调。
4. 软件启用异步任务号与跨重启恢复；与旧同步模型并存，按已验证能力路由。
5. 先部署兼容旧客户端的服务端，再启用新版软件能力；真实断网／重启小样通过后标记 B 完成。

回滚只停止新版本异步提交，保留已有任务查询、产物下载及持久记录；不能回滚到删除任务表，也不能把仍在生成的任务自动转为新生成请求。

交付记录需分别列明：软件测试结果、插件契约结果、适配器测试结果、实际部署版本、真实小样与账单核对结果。仅通过 mock 测试或仅改客户端，不标记端到端根治完成。

## 13. 本地实施记录（2026-10-17）

### A 阶段：软件端

- 图片模型在下载前将上游产物 URL／MIME／请求编号回调到原资产任务；下载失败时保留原任务和产物位置。
- 图片 URL GET 最多三次，有界处理 429／5xx／网络中断；私网与重定向地址校验、大小／长度／图片解码校验、临时文件及原子替换均在本地实现。失败不覆盖旧文件，也不重发生成 POST。
- 项目图片任务保留历史、阶段和造型归属；“继续取回”复用原 task_id，只下载／校验已有产物。API 普通响应隐藏签名 URL 和本地绝对路径。
- 工作台已有原位恢复按钮；恢复下载期间若用户改选主图，已下载图片保留为候选，不回滚用户选择，也不使分段失效。
- 本地 mock 覆盖 520 重试成功／耗尽、HTML／空文件／截断下载、私网重定向、签名地址脱敏、原位恢复不重新生成、重复点击去重及恢复期主图修改。

验证：Studio 图片传输／生产 pipeline／生产 API 测试 45 项通过；前端 typecheck 通过；资产工作台 UI 测试 2 项通过。当前 NewAPI 插件契约测试 24 项通过，仅证明现有同步图片合同不被本次改动破坏。

### B 阶段：尚未实施

当前 `comfy.plugin.js` 的图片提交等待最终结果，并以 `immediate` 返回成功；`listArtifacts` 没有图片产物合同。插件钩子禁止 JavaScript 异步语法，不等于宿主无法查询异步上游；须核对实际部署版本支持的任务协议。因此尚未改插件或适配器任务存储，未宣称解决“生成 POST 超时、URL 尚未返回”的丢失窗口。需要先确认所部署 NewAPI 的短提交、任务查询、图片产物鉴权和计费关联合同，必要时升级，再做适配器持久化与幂等。用户后续已改选局域网适配器直连，见 Windows 开发交接文档。

未验证：NewAPI／适配器部署版本、适配器 SQLite 重启恢复、宿主账单去重、真实网络中断与服务器重启小样。私网字面地址及私网重定向有测试；DNS 重绑定未做真实网络验证，故不将其表述为已完成全量 SSRF 验收。
