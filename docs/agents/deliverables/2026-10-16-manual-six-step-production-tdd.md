日期：2026-10-16

状态：待实施。本文定义本期手动版合同，新增字段、接口和测试尚未上线。

优先级：本期先实现本文。`2026-10-16-episode-preparation-runtime-tdd.md` 中的自动编排、暂停整条流程和“一键执行到底”延后；风格、四部分段包、尾镜、模型转写和合成的共同内容合同继续适用，冲突以本文为准。

## 1. 交付目标与产品取舍

用户点击首页「新建项目」，立即创建一个空白项目并进入新六步的第 1 步；不必先建系列，不必先粘贴剧本，不弹 R2V／I2V 技术模式选择，不执行任何付费生成。

六步固定为：

```text
1. 风格与制作设置
2. 工程剧本
3. 资产
4. 分段工程剧本
5. 分段视频
6. 整集合成
```

项目可以独立存在；系列承担风格／配置／资产的复用与剧集组织，不成为生产入口门槛。新系列创建剧集同样进入新六步。旧系列和旧项目维持原线路，不自动迁移既有内容。

本期以“产物交接”驱动：每一步有明确的输入、可编辑产物和下一步就绪条件，不用按钮点击次数或当前页序号代表完成。各步可自由查看；缺前置时只阻止生成／提交，允许浏览、粘贴、保存草稿和查看历史。

“保存并下一步”只保存并导航，不偷偷触发下游生成。“批量生成提示词”“批量生图”等由用户明确点击，在本步内处理指定对象。没有一个隐藏 Runtime 自动执行其他页面，也不增加通用流程编辑器。

## 3. 新建、路由与版本合同

### 3.1 点击即进入

1. 用户点击「新建项目」，按钮进入加载态，同一在途创建不能重复提交。
2. 发送草稿创建请求；标题使用可编辑的“未命名项目”，原文为空。
3. 创建成功只使用该响应返回的项目 ID 导航 `#/project/{id}`，不能从可能被其他请求改变的 `currentProject` 猜 ID。
4. 页面展示新六步，默认选中 `art_direction`；无 Key 也可以进入、编辑和保存。
5. 创建失败留在原页面并显示错误，不创建虚假本地成功项目，不导航到无效 ID。

保留当前 hash 路由与项目列表，不新建应用壳。项目标题在页头可编辑；剧本在第 2 步粘贴，允许用户提前查看该步并保存，生成时才检查风格。

刷新或重新打开新项目默认进入第 1 步，不会因此清空产物或重新生成。第一版不新增“恢复最后访问页”的持久化设置。

### 3.2 只增加流程版本字段

在 `Script` 与 `Series` 新增可选字段：

```text
production_workflow: "engineering_segments_v1" | null = null
```

新主入口显式提交 `production_workflow="engineering_segments_v1"`，仍使用既有 `workflow_mode="r2v"`。`production_workflow` 表示产品步骤与产物合同，`workflow_mode` 表示既有生成路径；二者不混用。

旧记录缺少字段就按旧 `workflow_mode / content_mode` 显示旧步骤。不能因为读到了 `r2v` 就把已有工程全部改成新六步；旧系列里新增剧集第一版继续旧路线，避免同系列混合两个合同。本期不做自动迁移或给旧系列默认打开新功能。

新系列由新建系列 UI 显式传入该字段，使用 `content_mode="scripted"`；其新剧集继承该版本。新流程不暴露 freeform 内容模式和首帧驱动的技术选择；历史功能继续按旧入口使用。独立项目不需关联系列也具备全部六步。

### 3.3 创建 API 的最小扩展

复用 `POST /projects`，新增可选字段，不另建一套项目 API。新主入口请求示例：

```json
{
  "title": "未命名项目",
  "text": "",
  "workflow_mode": "r2v",
  "production_workflow": "engineering_segments_v1"
}
```

客户端继续传 `skip_analysis=true`；服务端对新标识强制使用创建草稿路径，即使漏传该 query 也不能自动提取主体。创建新剧集额外传 `series_id`；服务端先验证系列存在及版本匹配，再分配集号、保存绑定，失败不遗留孤立项目。旧客户端未传标识时保持原语义。

创建本身不要求模型 Key、已选风格、有效视频通道或剧本。暂存的制作设置可以未完成；到第 1 步确认／后续生成时才做所需校验。

若存储项目与系列的两份 JSON 不能事务写入，使用稳定项目 ID 和既有系列绑定修复机制对账；写失败明确报错，重试关联不重复追加 episode ID，不把部分成功当全部成功。

## 4. 六步页面与手动操作合同

### 第 1 步：风格与制作设置

输入为用户选择／编辑的风格、画幅、图片模型、视频模型及真实通道、对应 H3／Seedance Skill、段长上限。复用 ArtDirection 与模型／Skill 设置组件，把本次相关设置放在一个页面，减少弹窗往返。

用户点击「确认制作方案」，保存风格正文、版本摘要、确认时间及当前制作参数。风格为最高创作准则，约束工程分镜、资产、段包与模型提示词；不能覆盖原剧情事实或删除原台词。风格默认、摄影机型号、光影与影像语言在此统一确定，下游不逐段另编。无 BGM 是本线路硬约定。

单段最大总时长由用户选择，包含末尾 1 秒全景：H3 路线产品上限为 27 秒，Seedance 为 29 秒，也可选更短值。实际可选项还要与视频通道和提示词 executor 的能力相交；不默认静默选择另一个模型补救。

已有项目风格为初始值；系列项目可显示已确认系列方案及其来源，用户确认后固定本项目版本。项目覆盖不反向修改系列。全局设置只作为新独立项目初始值，不覆盖已确认项目或系列继承值；文本模型仍沿用现有全局文本选择规则，不另造一套模型优先级。

产物为 `ProductionSettings` 和风格确认版本。保存草稿不等于确认；确认后编辑风格使确认失效，下游保留但标过期。仅改段长不要求重做角色图，按真实依赖失效。

### 第 2 步：工程剧本

用户粘贴／保存原始内容，点击「生成工程剧本」。所有新输入都经 gongchengjuben 按确认风格设计工程分镜；已有镜头文本也要经过同一规则核对。输入为空、风格未确认或模型不可用时阻止生成并说明原因。

原文与工程剧本分开存储和展示。用户可直接编辑工程剧本，再点击「校验并采用」。必须通过既有镜头、时间码、对白与景别解析检查；工程剧本本身就是分镜，不再用第二个 AI 重拆镜头。

产物绑定 `source_revision / style_revision / screenplay_revision`，具备连续镜头时间轴、原台词及动作节拍。采用前预览差异，保留旧版和既有分镜存档；采用成功后下一步才提取资产。

新流程不调用会把台本覆盖进 `original_text` 的旧确认路径；抽取共用校验／采用函数，保持历史路径默认行为。原文编辑器的 TipTap 文档也不能被生成文本静默覆盖。

### 第 3 步：资产

按以下明确按钮推进，输出都可修改和查看：

1. 「从工程剧本提取资产」：预览角色／场景／道具和已有匹配，用户采用后原位合并，绑定工程镜头。
2. 「生成资产提示词与声音设计」：为选择的缺失项生成角色／场景／道具提示词和角色声音九维档案；支持逐项生成与修改。
3. 「生成资产图」：为选择的资产出图，每项默认一版；可逐项重试、查看候选、手动采用。

提取必须使用已采用工程剧本，不使用仍在编辑的原文或旧台本。复用已知名称／别名与共享池；唯一命中复用 ID，歧义让用户选择，不再以新 `Script` 整体替换项目。未涉及的库资产不生成。

九维为年龄感、音高、明暗、厚薄、共鸣、气息、颗粒感、口音、稳定表达习惯。角色各段使用同一档案；表演情绪放工程剧本，不能每段重设计音色。只保存文字，不生成参考音，不调用 TTS；历史音频保留且不自动提交。

参考图沿用角色 `reference_sheet`、场景／道具 `image_asset` 和兼容的旧容器；无图先生成，有图可由用户复用／替换。锁定资产和人工采用版本不被批量操作覆盖；相异风格创建独立造型，保留原版。全局库只读复用，缺产物先按既有 fork 语义复制到本集／系列。

本集使用新主体：独立项目存本集，有系列则存系列池，并记录所属来源；避免第二集重复造同一角色。稳定匹配、共享写回与严格保存规则是本期业务能力，不等待 Runtime 才处理。

### 第 4 步：分段工程剧本

用户点击「生成分段工程剧本」，按第 1 步已选上限规划；查看每段时长、镜头、资产和空间继承。支持移动边界镜头、重新分段和编辑段包，再点击「校验并采用分段」。

`剧情预算 = 用户总时长上限 - 1 秒`；例如 27 秒最多 26 秒剧情＋1 秒全景，29 秒最多 28＋1。不是每段强制填满。换场优先分段；过长单镜在工程台本中按自然落点调整后重来，不能在分段时截对白、拉伸速度。

每段固定四部分：

```text
一、分段简介
分段简介：甲愤怒地咒骂他的妻子乙，乙默默承受。

二、参考资产
角色：名称、对应图片编号、完整声音九维档案。
场景：名称、对应图片编号、从资产提示词摘取的简单描述。
道具：名称、对应图片编号、从资产提示词摘取的简单描述。

三、确认风格
用户已经确认的同一版本风格全文；明确无 BGM。
保留工程剧本所需对白、环境声和动作音效。

四、本段工程剧本
开场承接：继承上一段结束的实际位置、朝向、距离、视线、持物和观察侧。
从 00:00 开始的连续局部时间码及剧情镜头。
结尾新增 1 秒全景，明确在场人物相对位置及场景地标。
```

四部分是唯一对外结构；空间承接写在第四部分，内部保留 `entry_state / exit_state`。简介是一句话的“主体＋关系＋情绪＋内容”，不是旁白或新增剧情。

尾镜按当时仍在同一场景中的人数写单人／双人／三人／多人全景，无人则空镜；不召回离场者，不强行把异地人物放到同框，不要求 1 秒内完成复杂后拉或新动作。该秒不新增对白，保留自然呼吸和余势。

下一段开场直接继承前段结束状态。用户修改尾镜位置时，同场下一段入口和受影响提示词标过期，不能独立改出矛盾站位。换场显式建立新空间。

新增尾镜只写派生分段版本，不污染原工程台本；重排不累计追加全景。源剧情镜头完整覆盖、无遗漏／重复；总计划时长＝剧情时长＋段数秒。采用分段后的手动修改也必须重新校验。

图号与实际上传清单共用一份有序映射，按稳定主体 ID 去重；页面按角色／场景／道具分组不重编号。包括尾镜所需资产，旁白没有图片时不伪造图号。声音档案完整重复，不用“同上”依赖别段上下文。

### 第 5 步：分段视频

复用视频任务、候选和预览组件，操作单位改为“已采用的一段”，不是每个源镜头。每段卡片有两个明确动作：

- 「生成视频提示词」：使用第 1 步所选 H3／Seedance Skill，输入已采用四部分段包、实际资产图和总时长。结果可预览、编辑并采用。
- 「生成本段视频」：提交已采用提示词和对应资产图，展示排队、上游处理、下载及最终视频，支持候选选择和失败恢复。

本期先支持逐段操作；不增加跨六步自动执行。“生成提示词”不自动提交视频，“生成本段视频”不在提示词缺失时暗中调用另一个文本模型。

最终提示词须保留确认风格、九维声音、原台词、全部镜头和末尾 1 秒全景，按实际图号输出，无 BGM、无虚构参考音标签。人工编辑后提交也重新验证引用、段版本与请求参数一致，不能默认“用户改过就不检查”。

Skill 与视频通道分别有 ID 和版本。现有 H3 Context IR 本地入口是 4–15 秒校验，不能直接接 27 秒；长段须使用经验证的长段文本转写模板／executor。Seedance 选用适配工程台本转写的 Skill，不凭空依赖不存在的卷轴图。

H3 27 秒需选择支持对应长度的实际参考生视频通道；Seedance 29 秒选择变长通道，不能把固定 30 秒通道当成 29 秒，也不静默生成 30 秒再裁。提示词长度、图片数量、最短时长及 step 同时检查，不只检查上限。

每个视频任务绑定不可变段版本、总时长、源镜头与尾镜、提示词和素材版本。现有 `create_video_task` 会把时长重算为源镜头之和，新增受校验的段入口把尾镜纳入，不能在适配器前丢掉这一秒。

保存上游号后才继续轮询；下载失败只重试下载，“继续取回”与“重新生成”分清。创建响应丢失标待核实，不自动重复付费提交。视频已返回但文件没落地不算完成。暂停／取消本地等待不声称上游已停止或退款。

本流程禁用应用的独立 `generate_audio` 前置步骤，无 `audio_url`／参考音列表；视频模型的同期对白与音效按通道真实原生能力启用。无 BGM 不等于静音，通道不支持所需声音则提交前明确报错。

### 第 6 步：整集合成

按本项目当前采用分段方案展示有序段清单、实际采用的视频候选和缺口。用户点击「拼接整集」；生成整集后可播放、下载，各段仍独立保留。

严格按 `segment_id → selected_video_task_id` 各取一次，不按每个源 frame 重复加入整段视频，也不使用历史首个成功候选。必须全段有可用本地文件、来源版本有效且媒体参数兼容，缺段不能静默跳过。

默认硬切并保留每段最后 1 秒全景；必要转码只统一编码／fps／分辨率，不拉伸内容或裁对白。整集时长等于选中各段之和，按帧粒度容差核对。

显式禁用 Runtime 文档同样规定的 BGM 混音路径，即使旧项目设置中存在 `bgm_url` 也不自动应用；不修改其历史设置。合成成功才更新 `merged_video_url`，文件名唯一，旧成片保留；合成失败不会要求重新生成所有视频。

## 5. 持久化、版本及手动完成状态

本期需要业务产物与单次异步操作状态，不需要 `PreparationRun`、跨阶段 scheduler 或全链路 worker。沿用既有项目／系列 JSON 和原子保存，新增字段均有兼容默认值。

| 数据 | 最小合同 |
| --- | --- |
| `production_workflow` | 新六步版本标识；旧记录 `null` |
| `production_settings` | 当前确认方案：风格正文及摘要、确认时间、画幅、模型与通道、Skill／executor、段长上限、`tail_seconds=1`、`bgm=none` |
| `engineering_script` | 原文版本、风格版本、台本 revision、可编辑台本文本及解析镜头；旧台本无新字段时保持旧判断 |
| 角色 `voice_design` | 可选结构化九维、版本、来源和确认／采用信息；兼容展示既有声音描述，不默认生成试听音频 |
| `segments` | 稳定段 ID、顺序、源镜头及派生尾镜、剧情／总时长、四部分内容、entry／exit、来源摘要、采用版本 |
| 段视频提示词 | Skill／executor、输入段版本／素材顺序、生成或手动来源、采用文本与摘要 |
| `VideoTask` 扩展 | 可选段 ID／版本和段输入快照；已有上游号、视频路径与候选机制继续复用 |
| 段采用视频映射 | 明确保存每段选中 task ID；不把同一段 ID 填进多个 frame 作为合成依据 |

各步骤状态由产物、依赖摘要和文件有效性推导：未开始、处理中、可继续、需更新、失败／缺前置。不仅用“有没有字段”推定已完成；导航能点击不意味着允许发起缺前置的请求。

失效沿真实消费关系传播：原文／风格变更影响工程台本及下游；资产换图影响相关段包／提示词／视频；九维改动影响有关角色的视频输入；段长改变影响分段及下游；视频候选切换只影响整集合成。旧文件、候选和人工修改保留，不自动重跑、不静默覆盖。

生成前固定本次输入快照；返回时复核来源版本，不把迟到响应覆盖到用户的新稿。多个接口都使用同一生成前校验与写回函数，前端禁用按钮不能代替服务端校验。

异步操作复用可持久化的任务 ID／状态／输入摘要／产物引用；现有仅内存保存的任务在本期补齐恢复记录。单次操作的幂等与恢复不等待后续 Runtime；但不为此创建一套任意工具执行平台。

模型调用前严格保存请求意图，保存失败禁止调用；图像／文本不确定响应不能盲重试，视频有上游号先对账。项目与系列写回遵循资产所属来源，写盘错误需抛出，不可只记日志后显示成功。

## 6. 后端业务接口与共用边界

优先扩展既有接口／抽出既有业务函数。以下为必须提供的动作语义，不要求每个按钮各造一套模型适配器：

| 动作 | 接口／业务合同 |
| --- | --- |
| 创建草稿 | 既有 `POST /projects` 扩展流程标识，系列绑定同请求 |
| 保存／确认制作设置 | 既有风格及设置保存能力加确认版本；普通保存不能代填用户确认时间 |
| 生成／采用工程台本 | 既有标准化与工程解析逻辑共享；来源原文与派生台本分离，采用时复核 revision |
| 提取／采用资产 | 既有提取 preview 加工程台本来源；采用为原位合并，保留其他业务字段 |
| 提示词／九维／生图 | 复用现有资产和声音文字能力，统一模型、风格、画幅解析及所选对象范围 |
| 规划分段 | `POST /projects/{id}/segments/plan`，基于已确认参数和台本；返回四部分预览及新 revision |
| 修改／采用分段 | 对完整覆盖关系和受影响邻段进行服务端验证；单独改一句文本不能绕过时长或身份校验 |
| 生成段提示词 | 受段 ID／revision 约束的动作，保存 Skill、图号顺序和结果；提交即返回可查询任务 |
| 生成段视频 | `POST /projects/{id}/segments/{segment_id}/video-tasks`，请求含预期段／提示词 revision；参数由服务端快照组装 |
| 选择段候选 | 显式关联本段已完成 task；拒绝其他项目／其他段视频，旧段版本需用户明确替换或更新后使用 |
| 拼接 | 既有合成能力增加严格有序段入口，按采用 manifest 和预期 revision 校验；强制无 BGM |

生成动作是异步 `202 + task_id`，只读 GET 查询状态不提交生成。缺风格、版本过期、缺图、模型能力不符在付费调用前报错；参数校验 `422`，版本／资源冲突 `409`，不存在项目／段 `404`，上游失败保留可读原因。

后续 Runtime 将直接调用这些已有业务函数；前端与未来自动执行器共用输入、校验、版本和产物合同。自动化只增加调度，不再实现另一套台本／分段／生图逻辑，这是本期为后续保留的唯一必要边界。

## 8. 分批实施与验收测试

### A. 新入口和六步骨架

先补 `project-steps.test.ts` 和创建 UI 测试：新标识准确返回 `art_direction / script / cast / segments / segment_video / assembly`；新项目默认第 1 步，切项目重置导航；旧 scripted／freeform／legacy 期望维持。

后端创建测试：空文本新项目创建成功、无 Key 可创建、未传 skip query 也不触发 LLM；无效系列不留项目；新剧集继承版本且绑定一次。前端断言主入口不弹技术模式选择、不依赖系列、双击在途只提交一次、使用响应 ID 导航。

验收：点击任意首页主“新建项目”入口即可看见六步及第 1 步；刷新仍是同一项目，创建过程中付费生成调用数为零。

### B. 风格、工程台本与资产

测试风格显式确认／编辑失效／系列继承／项目覆盖，确认方案不被本地默认值回填覆盖；所有新内容均先走工程 Skill，原文不变，非法台本不可采用；从已采用台本提取主体且原位合并不丢视频和历史素材。

测试九维齐全并稳定绑定角色、没有参考音／TTS 调用；批量只处理所选项，唯一主体复用、歧义需要选择、全局库只读、图片旧容器兼容与选定版本保留。

验收：用户逐次点击可获得工程剧本、已绑定主体、图片和九维文字；每个产物在原页面可编辑、保存、刷新恢复。

### C. 分段工程剧本

测试 27＝26＋1、29＝28＋1、较短上限、模型最短长度和固定／枚举步长、超长单镜、换场、边界修改及完整覆盖。每段严格四部分，图号对应提交顺序、角色九维完整、场景道具描述有来源，风格正文一致且无 BGM。

测试尾镜恰好 1 秒、人数取当时在场者、下一段入口继承、局部时间码从零连续、重复重排不增加尾镜、不修改原工程镜头。编辑和采用均不能越过服务端验证。

验收：手动生成、修改并采用分段方案，所有段的四部分内容能直接用于第 5 步。

### D. 分段视频

测试 H3／Seedance 转写保留台词、风格、声音和尾镜；无虚构图／音编号；27 秒不误走现有 4–15 秒 IR 入口，29 秒不误走固定 30 秒通道。

测试两个按钮互不暗中触发；任务 duration 包含尾镜；稳定输入快照与迟到响应保护；上游号落盘；下载失败回捞不重发；跨项目／跨段候选拒绝；生成旧版本不覆盖当前采用版本。

验收：用户在一段内依次生成提示词和视频，返回的视频可预览和选择，刷新后任务与候选可恢复。

### E. 严格拼接和端到端手动验收

测试一个视频覆盖多个源镜头时只拼一次；缺段／缺文件／旧 revision 阻止整集完成；全部段按采用顺序；旧 BGM 设置不生效；尾镜完整保留；失败只重试合成，旧成片不丢失。

通过假适配器完成从“新建项目”到合成的六步 UI 测试，再做类型检查、相关 node／UI 测试及后端回归。真实模型小样另行记录能力、时长和效果，不能把假测试当成视频质量验证。

总体验收：无现成系列、无原始文本的新用户也能点击新建进入六步；手动完成一集，所有中间产物可检查与修改，逐段结果及整集可播放下载；没有任何步骤要求先运行自动执行器。

## 9. 本期限制与下一阶段

本期不交付全链路自动运行、跨步批量调度、多集并发、自动挑最佳版本和旧项目迁移。单次生成可以后台执行，但下一步何时执行由用户点击。

文字风格、九维音色和空间继承有助于指导生成，不能承诺模型跨段像素或音色完全一致；最后 1 秒全景及无 BGM 必须在真实小样核对。具体通道与 executor 不支持目标时长时应显示不兼容，不以隐藏裁剪／换模型掩盖。

后续自动化在这条手动链路验收通过后再接：沿用同一段包和业务函数，将现有手动动作组成固定调度。手动版不是自动 Runtime 的前端皮肤，而是两者共用的完整制作基础。
