# 顶层提示词编辑合同

版本：v1.1
日期：2026-10-05
状态：v1.0 基础功能已实施，用户已确认可用；v1.1 五项升级方案已获用户同意，本次仅统一合同，升级功能尚未实施。此前 TypeScript 编译通过，未执行完整交互验收或真实模型生成。

## 1. 目标与范围

在顶层新增「提示词编辑」，复用项目内的编辑器、AI 预览和 Skill 管理，完成：

**独立文档＋可选风格＋参考图片 → 可选 Skill／描述生成或修改 → 接受预览 → 用于创作台。**

范围包含顶层入口、独立文档、通用文字与图片理解、风格库和资产图联动、创作台文本与参考图片带入，以及统一 Skill 管理。多 Skill 串联、自动执行工具、自动创建资产或项目、自动生成媒体均不在本期范围。

## 2. 页面与复用合同

- 顶层导航顺序：工作区、资产库、提示词编辑、创作台；设置沿用现有位置。
- 页面不要求项目 ID、系列或集数，不创建隐藏项目来承载文档。
- 左侧为现有编辑器；右侧复用 Skill 选择／上传／管理、本次要求和发送面板。新增可折叠的「风格」「参考图片」输入区，不另建复杂工作台。
- 正文和 AI 预览使用清晰可见的圆角边框、独立底色及内边距；浅色主题使用白底，深色主题使用对应面板色。分别标记「正文」「AI 结果预览」，保留接受／放弃按钮。
- 空正文显示「在这里输入内容，或在右侧描述你想生成什么」；编辑区域有稳定的最小高度，长文本在原编辑区域滚动。
- 顶部提供文档名、新建、文档切换、保存状态、历史、撤销／重做和「用于创作台」。历史指已保存的文档版本，不新增聊天历史系统。
- 项目和顶层共用编辑组件，以显式用途区分 `script` 与 `prompt`，不复制整套编辑器。
- 顶层不展示剧本格式、场景计数、提取实体、工程台本确认和制作管线控件；使用通用文本节点，禁止自动按剧本规则改写粘贴文本或 AI 输出。
- 项目编辑器继续使用项目数据、剧本规则和已有工程台本流程；本合同只新增通用用途，不取消项目用途的规则。

## 3. 文档与保存合同

- 提示词文档使用独立 ID、名称、编辑内容及创建／更新时间，后端独立持久化；不得写入项目剧本、分镜或工程台本。
- 默认进入最近使用的文档；没有文档时直接提供可编辑的空白文档。新建／切换前完成保存，保存失败要明确反馈。
- 文档支持自动保存、手动保存和版本恢复，复用现有保存／快照交互。保存状态只能在后端成功后标记「已保存」。
- 正文及换行是内容来源；不得经剧本解析后再反向生成正文。刷新／重启后可恢复已保存正文和文档名称。
- AI 未接受的结果为预览，不写入正文或已接受版本；接受前保留可恢复的原正文。放弃只关闭预览。
- 切换文档清除选区、旧预览和当前修改要求；保留该页面上次选择的 Skill。进行中的 AI 结果只能回到发起它的文档，不得落入后来打开的文档。

## 4. 输入与 AI 输出合同

| 条件 | 行为 |
|---|---|
| 正文为空，本次要求非空 | 从零生成 |
| 正文非空，未主动框选 | 处理全文 |
| 主动框选有效文字 | 只处理该选区 |
| 未选择 Skill | 按本次要求生成／修改 |
| 已选择 Skill | 按 Skill 规则结合本次要求处理 |
| 正文和本次要求均为空 | 禁止发送，仅选择 Skill 不构成输入 |
| 未选择 Skill且本次要求为空 | 禁止发送，提示填写要求 |

- 右侧明确显示「从零创作／全文／已选 N 字」；点击 Skill、要求输入框或发送按钮不应丢失主动选区。
- 选区必须属于当前文档并与当前正文一致。切换文档／恢复版本／接受修改后清除旧选区，不允许残留“已选 5 字”等旧状态。
- 通用用途取消“只返回剧本文本”的后台要求。输出可为普通文本、Markdown、JSON、提示词或其他文字内容；不强制双语、不套固定 JSON、不自动删除代码围栏或改写格式。
- 有 Skill 时按其格式要求输出；本次明确要求与 Skill 冲突时，以本次要求为准。没有要求修改的内容不擅自缩写、增删或标准化。
- 上传 Skill 的能力沿用现有导入格式，主要提供文字规则；不会自动执行其工具、脚本或外部文件引用。遇到缺少材料，应指出缺少什么，不得声称已读取或执行。
- 请求超时、失败、空输出或模型返回截断标记时明确反馈；保留原文，不自动接受不完整输出。输入过长也不得静默裁剪。
- 复用现有 AI 预览、接受和放弃。选区模式接受后只替换原选区；全文模式替换全文；空白生成写入新正文。
- 请求发出后正文若发生变化，接受前校验发起时的文档及正文版本；不得用旧请求结果覆盖新编辑。提示重新生成或将结果复制出来。

## 5. Skill 合同

- 复用现有全局 Skill 存储和管理入口，不建立第二套 Skill 库，不批量迁移已有 Skill。
- 顶层管理器统一展示现有文字 Skill 和应用内置 Skill 包，包含主规则及其附属规则文件；不止展示当前 script、motion 列表。指应用已有内置 Skill，不自动导入电脑上全部 Agent Skill。
- 复用既有存储，按来源与稳定 ID 统一列表及有效内容读取，不复制第二套库、不批量迁移记录。兼容现有 Skill ID、用途绑定与项目筛选。
- 提供搜索及「全部／内置／自定义／已隐藏」筛选。支持上传、查看、编辑、重命名、隐藏／恢复及导出；包的附属文件继续按现有包路径和文件限制管理。
- 内置 Skill 可以直接编辑、保存；修改存为同一内置 ID 的个人覆盖版本，保留默认文件。升级不覆盖个人修改；「恢复内置默认」明确确认后撤销该覆盖并保留恢复前的可恢复副本。
- 内置隐藏不删除默认文件；自定义删除／恢复沿用现有规则，影响范围在操作前明确展示。导出内置覆盖版本时包含有效主规则及附属文件。
- 各功能入口按同一 ID 读取有效内容；管理保存后刷新选择器，后续请求使用新内容。已有请求仍使用原快照，项目中的用途筛选不因统一管理而失效。
- 顶层与项目分别记住上次选择；首次进入顶层默认「不使用 Skill」。所记 Skill 不存在或已隐藏时回退到不使用 Skill并明确提示。
- 请求记录使用的 Skill 内容快照，管理中的后续编辑不改变已经发出的请求。

## 6. 用于创作台合同

- 「用于创作台」选择：图片、视频、音频。
- 数据来源为已接受、可编辑的正文：有有效选区则使用选区，否则使用全文。未接受的 AI 预览不能直接带入，先接受或自行复制。
- 正文和选区为空时禁止带入；显示本次带入范围及字数。
- 若创作台已有提示词，让用户选择「替换／追加／取消」。追加使用换行分隔；取消不修改目标内容。
- 默认带入文本；存在参考图片时提供「同时带入参考图片」选项，默认勾选，可取消。风格已用于 AI 生成，不在带入时重复拼接风格描述，不推断 JSON 字段。
- 同时带图时，保留图片顺序与引用来源。创作台已有素材则展示最终素材列表，让用户选择替换／追加／取消；只有明确确认才能替换已有素材。文本与图片作为一次操作校验，任一不兼容都不部分写入。
- 文本追加与图片追加分别明确显示，不把“追加文字”理解为“追加图片”。Image X 必须对应最终参考图顺序；若已有素材导致编号冲突，先展示绑定关系要求处理，不能静默重排、改写正文或提交错误绑定。
- 不改变负面提示词、生成参数或项目资产，不自动生成媒体。
- 仅带文字时沿用已有类别切换规则：同类别保留模式，否则切换文生图／文生视频／文生音频。
- 带图片用于图片生成时进入支持参考图片的图片编辑模式；用于视频时使用支持该参考图数量的图生／参考生模式，并在确认中展示目标模式。多图不能静默切为仅支持一张首帧的模式。音频仅带文本，本期不向音频模式注入图片。
- 适用的已有模型保留，否则使用创作台现有默认选择逻辑；不根据 Skill 内容推测并指定模型。模型或模式无法接收这些图片时明确提示选择或处理，禁止静默丢图。
- 文本长度、图片数量、类型与大小按实际目标模式／模型限制检查，超限阻止带入并给出具体提示，不静默截断或裁掉图片。
- 带入成功后导航到创作台并显示反馈，不自动提交生成、不自动计费。原提示词文档继续保留，返回后可继续编辑。

## 7. 风格、参考图片与读图合同

### 7.1 风格库

- 复用现有风格库数据、卡片与详情，提供选择、查看、切换、清除；本期每份文档选择一个风格。
- 选择后显示名称，并将有效风格描述作为 AI 上下文；不会直接改正文，也不会更改项目或系列风格。
- 文档保存风格来源 ID、名称及描述快照；库中后续修改不静默改变文档上下文，可由用户重新选取更新。
- 风格约束视觉表达，不覆盖明确的用户要求或擅自改变人物身份、动作与剧情。参考图中的身份与服装由用户要求决定是否保持或修改。

### 7.2 资产图与上传

- 复用创作台参考图 UI、上传接口及 AssetPickerModal：本地上传、拖拽上传、从资产库选取。组件接收当前文档的素材状态，不直接读写创作台素材状态。
- 资产选择覆盖现有可访问角色、场景、道具图片；只引用被用户选中的图片，不自动携带整个项目资料。
- 每张显示缩略图、名称及 Image 1、Image 2……，支持顺序调整和移除。相同来源避免重复添加；不同图片不按文件名误去重。
- 文档保存有序图片引用、来源、名称及相关资产文字快照。移除只解除文档引用，不删除上传文件或资产原图。
- 图片不可读、已丢失或上传失败时明确展示并允许移除／替换；不得静默略过仍被选中的图片。上传和读图限制须在 UI 展示，并由后端校验，不能无限上传或只做前端限制。
- 默认图片作为生成上下文而非正文替换范围；选区修改仍只替换选区。修改参考图顺序后提示检查已有正文中的 Image X，不能自动改写已接受正文。

### 7.3 真正读图

- 使用已有文本模型配置和适配器能力，在发送请求中传递可供模型读取的图片内容，同时发送 Image X 编号、资产说明、风格快照、正文／选区、Skill 快照和本次要求。
- 用户点击现有「发送」触发理解和生成，不因上传图片自动调用模型。图片存在、正文为空时也必须填写本次要求，避免没有任务就消耗调用。
- 后端解析应用管理的图片引用，按现有媒体能力读取，不能仅把本地路径字符串写进提示词冒充读图。
- 当前模型不支持图片、通道拒绝图片或图片无法读取时明确反馈，保留文档及素材；不偷偷降级为纯文字，不未经用户选择自动换模型。
- 请求使用风格、图片顺序及 Skill 内容快照。接受结果时同时校验正文和上下文是否变化；变化则要求重新生成或复制结果，不能接受过期绑定。
- 保持 v1.0 的输出格式与预览合同；不把图片读图扩展成自动生图、自动执行 Skill 工具或自动生成资产。

### 7.4 持久化与恢复

- 自动保存、手动保存、历史快照覆盖正文、名称、所选风格及有序图片引用；恢复版本时恢复整份文档上下文，恢复前先保存可恢复副本。
- 兼容已有 v1.0 文档，缺失风格／图片字段按未选择／空列表处理；不得因升级丢失原正文或历史。
- 切换文档正确切换风格和图片，清除旧选区与预览；正在执行的请求不能落入其他文档。

## 8. 实施落点与顺序

1. 正文及 AI 预览增加可见边框、背景、标题和空白引导。
2. 接入风格库及参考图片区；先扩展文档与版本数据，保证旧文档兼容。
3. 接入上传与资产选择，扩展后端及现有模型适配器的图片理解请求。
4. 升级创作台带入确认：文本、图片顺序、模式兼容及数量校验。
5. 同一 Skill 管理器汇总文字记录和内置包，接入覆盖版本、默认恢复及各入口有效内容读取。

不为本期引入新的工作流引擎、Skill 输出类型系统或整套编辑器。复用组件通过显式数据和回调适配文档，不能借复用引入项目或创作台全局状态的串扰。

## 9. 验收合同

以下是后续实施的验收依据，并非本次已执行的测试：

1. 没有任何项目也能新建文档，选择 Skill、输入要求并生成预览。
2. 不使用 Skill 也能从零生成／修改；空输入不能发送。
3. 中文、英文、Markdown、JSON 和换行不经剧本标准化处理。
4. 全文与选区范围准确；切换文档后旧选区不会跟随。
5. 接受／放弃、撤销／重做、自动保存和历史恢复有效；重启可恢复正文。
6. 请求失败、截断、旧文档结果或正文版本变化均不会覆盖现有内容。
7. 同一 Skill 的管理修改能在顶层与项目页看到，页面的选择记忆互不干扰。
8. 图片／视频／音频带入正确；替换、追加、取消和超长处理符合约定；不自动生成媒体。
9. 顶层文档与项目数据互不覆盖，已有剧本、工程台本确认及分镜同步继续按原合同工作。
10. 正文、预览和空白状态清晰可辨；编辑、长文本滚动及预览接受按钮不受新增输入区影响。
11. 风格选取可查看／清除，参与生成；刷新、切换文档和版本恢复保持对应风格，不改项目风格。
12. 上传、拖拽、资产选图及排序／移除有效；Image X 与实际送给模型的图片顺序一致，原素材不被删除。
13. 图片真正进入模型请求；不支持读图和图片读取失败明确报错，不伪装成功，不覆盖正文。
14. 带图进入创作台保留正确引用；已有素材替换／追加／取消、编号冲突及超数量场景均明确处理，不静默丢图或部分写入。
15. 所有应用内置 Skill 与自定义 Skill 可在同一管理器查找；内置直接编辑、升级保留覆盖、隐藏／恢复及恢复默认符合约定，各功能后续请求读取同一有效版本。
16. 旧文档和旧 Skill ID 兼容；正文、风格或参考图片在请求过程中变化时，旧结果不会被接受为新上下文结果。

## 10. 与既有合同的关系

本合同统一本次顶层提示词编辑功能。`docs/design/script-editor-optimization-contract.md` 中的编辑基础能力和主题规则继续适用；其“本期不新增 AI 业务能力”仅描述此前优化任务，不限制本合同新增的通用用途。

后续实现以本合同为依据；改变输入范围、输出处理、项目隔离或自动生成边界时，应先同步本合同。

## 11. v1.1 对 v1.0 的明确变更

- 将纯文本带入扩展为可选文本＋参考图片带入；新增素材确认与兼容检查，取代旧版“不绑定参考图”的限制。
- 将内置 Skill 只读／复制编辑扩展为同 ID 个人覆盖编辑及恢复默认；统一展示应用内置包和文字 Skill，取代旧版仅 script、motion 记录范围。
- 扩展文档及历史版本的上下文数据，保留原有独立文档、预览接受、项目隔离和禁止自动生成媒体的边界。
- 本次工作仅更新合同；以上五项升级不能因写入合同被标记为已实现或已验收。
