# 顶层提示词编辑合同

版本：v1.0  
日期：2026-10-05  
状态：功能代码已实施；TypeScript 编译通过，应用已启动；尚未执行交互验收或真实模型生成

## 1. 目标与范围

在顶层新增「提示词编辑」，复用项目内的编辑器、AI 预览和 Skill 管理，完成：

**独立文档 → Skill／描述生成或修改 → 接受预览 → 用于创作台。**

本期仅包含顶层入口、独立文档、通用文本生成和创作台文本带入。多 Skill 串联、自动执行工具、自动创建资产或项目、自动生成媒体均不在本期范围。

## 2. 页面与复用合同

- 顶层导航顺序：工作区、资产库、提示词编辑、创作台；设置沿用现有位置。
- 页面不要求项目 ID、系列或集数，不创建隐藏项目来承载文档。
- 左侧为现有编辑器；右侧复用 Skill 选择／上传／管理、本次要求和发送面板。
- 顶部提供文档名、新建、文档切换、保存状态、历史、撤销／重做和「用于创作台」。历史指已保存的文档版本，不新增聊天历史系统。
- 项目和顶层共用编辑组件，以显式用途区分 `script` 与 `prompt`，不复制整套编辑器。
- 顶层不展示剧本格式、场景计数、提取实体、工程台本确认和制作管线控件；使用通用文本节点，禁止自动按剧本规则改写粘贴文本或 AI 输出。
- 项目编辑器继续使用项目数据、剧本规则和已有工程台本流程；本合同只新增通用用途，不取消项目用途的规则。

## 3. 文档与保存合同

- 提示词文档使用独立 ID、名称、编辑内容及创建／更新时间，后端独立持久化；不得写入项目剧本、分镜或工程台本。
- 默认进入最近使用的文档；没有文档时直接提供可编辑的空白文档。新建／切换前完成保存，保存失败要明确反馈。
- 文档支持自动保存、手动保存和版本恢复，复用现有保存／快照交互。保存状态只能在后端成功后标记「已保存」。
- 正文及换行是内容来源；不得经剧本解析后再反向生成正文。刷新／重启后可恢复已保存正文和文档名称。
- AI 未接受的结果为预览，不写入正文或已接受版本；接受前保留可恢复的原正文。放弃只关闭预览。
- 切换文档清除选区、旧预览和当前修改要求；保留该页面上次选择的 Skill。进行中的 AI 结果只能回到发起它的文档，不得落入后来打开的文档。

## 4. 输入与 AI 输出合同

| 条件 | 行为 |
|---|---|
| 正文为空，本次要求非空 | 从零生成 |
| 正文非空，未主动框选 | 处理全文 |
| 主动框选有效文字 | 只处理该选区 |
| 未选择 Skill | 按本次要求生成／修改 |
| 已选择 Skill | 按 Skill 规则结合本次要求处理 |
| 正文和本次要求均为空 | 禁止发送，仅选择 Skill 不构成输入 |
| 未选择 Skill且本次要求为空 | 禁止发送，提示填写要求 |

- 右侧明确显示「从零创作／全文／已选 N 字」；点击 Skill、要求输入框或发送按钮不应丢失主动选区。
- 选区必须属于当前文档并与当前正文一致。切换文档／恢复版本／接受修改后清除旧选区，不允许残留“已选 5 字”等旧状态。
- 通用用途取消“只返回剧本文本”的后台要求。输出可为普通文本、Markdown、JSON、提示词或其他文字内容；不强制双语、不套固定 JSON、不自动删除代码围栏或改写格式。
- 有 Skill 时按其格式要求输出；本次明确要求与 Skill 冲突时，以本次要求为准。没有要求修改的内容不擅自缩写、增删或标准化。
- 上传 Skill 的能力沿用现有导入格式，主要提供文字规则；不会自动执行其工具、脚本或外部文件引用。遇到缺少材料，应指出缺少什么，不得声称已读取或执行。
- 请求超时、失败、空输出或模型返回截断标记时明确反馈；保留原文，不自动接受不完整输出。输入过长也不得静默裁剪。
- 复用现有 AI 预览、接受和放弃。选区模式接受后只替换原选区；全文模式替换全文；空白生成写入新正文。
- 请求发出后正文若发生变化，接受前校验发起时的文档及正文版本；不得用旧请求结果覆盖新编辑。提示重新生成或将结果复制出来。

## 5. Skill 合同

- 复用现有全局 Skill 存储和管理入口，不建立第二套 Skill 库，不批量迁移已有 Skill。
- 顶层可选择现有 script、motion Skill；项目页保留其原有筛选规则。顶层上传的 Skill 与项目编辑器共用同一条记录，通过现有兼容类别管理。
- 上传、查看、编辑、重命名、删除／恢复能力沿用当前实现及内置 Skill 保护规则；管理修改后刷新使用同一条记录的页面。
- 顶层与项目分别记住上次选择；首次进入顶层默认「不使用 Skill」。所记 Skill 不存在或已隐藏时回退到不使用 Skill并明确提示。
- 请求记录使用的 Skill 内容快照，管理中的后续编辑不改变已经发出的请求。

## 6. 用于创作台合同

- 「用于创作台」选择：图片、视频、音频。
- 数据来源为已接受、可编辑的正文：有有效选区则使用选区，否则使用全文。未接受的 AI 预览不能直接带入，先接受或自行复制。
- 正文和选区为空时禁止带入；显示本次带入范围及字数。
- 若创作台已有提示词，让用户选择「替换／追加／取消」。追加使用换行分隔；取消不修改目标内容。
- 只传递文本及媒体类别，不推断 JSON 字段、不自动选择模型、不绑定参考图、不改变已有素材、负面提示词或生成参数。
- 进入创作台时：若当前模式已属于所选类别则保留；否则切换到对应文生图／文生视频／文生音频。模型不适用于目标类别时使用创作台现有默认选择逻辑。
- 文本超过目标输入的实际限制时阻止带入并给出字数提示，不静默截断。
- 带入成功后导航到创作台并显示反馈，不自动提交生成、不自动计费。原提示词文档继续保留，返回后可继续编辑。

## 7. 实施落点

1. 为现有编辑器及 AI 面板增加通用用途适配，保留项目用途路径。
2. 增加独立提示词文档的存储／版本接口，以及不依赖项目的通用 AI 文本接口；复用现有模型配置和错误处理。
3. 增加顶层页面与导航，接入现有 Skill 管理。
4. 对接创作台提示词状态，实现类别切换、替换／追加、长度校验和导航。

不为本期引入新的工作流引擎、Skill 输出类型系统或整套编辑器。

## 8. 验收合同

以下是后续实施的验收依据，并非本次已执行的测试：

1. 没有任何项目也能新建文档，选择 Skill、输入要求并生成预览。
2. 不使用 Skill 也能从零生成／修改；空输入不能发送。
3. 中文、英文、Markdown、JSON 和换行不经剧本标准化处理。
4. 全文与选区范围准确；切换文档后旧选区不会跟随。
5. 接受／放弃、撤销／重做、自动保存和历史恢复有效；重启可恢复正文。
6. 请求失败、截断、旧文档结果或正文版本变化均不会覆盖现有内容。
7. 同一 Skill 的管理修改能在顶层与项目页看到，页面的选择记忆互不干扰。
8. 图片／视频／音频带入正确；替换、追加、取消和超长处理符合约定；不自动生成媒体。
9. 顶层文档与项目数据互不覆盖，已有剧本、工程台本确认及分镜同步继续按原合同工作。

## 9. 与既有合同的关系

本合同统一本次顶层提示词编辑功能。`docs/design/script-editor-optimization-contract.md` 中的编辑基础能力和主题规则继续适用；其“本期不新增 AI 业务能力”仅描述此前优化任务，不限制本合同新增的通用用途。

后续实现以本合同为依据；改变输入范围、输出处理、项目隔离或自动生成边界时，应先同步本合同。
