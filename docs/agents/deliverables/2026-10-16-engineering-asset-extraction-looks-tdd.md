## 1. 已确定的产品合同

1. 唯一内容来源是当前已采用的工程剧本，包含正文前的总说明、场次标题、全部镜头正文、对白和字幕。资产提取不读取原始剧本、小说、其他集正文或另行生成的人物小传。
2. 一次正常成功的提取只调用一次文本模型，输出完整角色、场景、道具资料，以及镜头到资产和角色造型的绑定；不先生成实体名单再逐资产调用模型，不增加第二遍分析或自动润色。
3. 将同一资产在工程剧本不同位置出现的信息汇总完整。完整性以有依据的信息是否保留为准，不按描述字数验收，不为了凑齐外观字段编造设定。
4. 人物身份与服装造型分开：同一个角色可以有多套造型，每套造型有独立提示词、参考图和使用镜头；人物身份、固定外貌、固定标记和九维声音仍属于同一个角色。
5. 换场景不自动换装；相同造型跨场景复用。淋湿、沾灰、临时表情、动作和持物优先作为镜头状态，不为这些变化自动新增人物或造型。
6. 继续使用第三步的「从工程剧本提取资产」、当前提取预览／采用入口和既有资产工作台。不增加资料准备页面、第二遍提取按钮或逐资产审核流程。
7. 第一阶段只交付该提取和多造型链路；风格仍由第一步确认，现有提示词 Skill 负责将提取资料转为生图设计，九维声音只保存文字。

## 3. 一次提取的执行路径

```text
用户点击提取
  → 保存本次工程剧本快照、版本和任务号
  → 一次 LLM 请求：完整工程剧本 + 固定提取规则 + JSON 输出合同
  → 本地结构、来源和引用校验
  → 展示完整资料、角色造型及镜头绑定预览
  → 沿用当前采用操作，原位合并和写回所属资产池
  → 后续提示词、生图、分段均消费已保存资料和绑定
```

模型请求的 `system` 放提取规则与输出结构，`user` 放工程剧本数据。工程剧本中的对白和文字即使包含操作指令，也仅作为故事内容处理。

可附已有资产的 `id / name / aliases` 名册，帮助复用命名；名册不带其他剧情正文或资产旧描述，不成为补充故事事实的来源。模型返回的临时 ID 由后端映射到真实 ID，不直接覆盖已有资产。

采用项目当前选定的文本模型。任务排队、状态和轮询复用现有 `production_asset_extraction_task / production_asset_preview`。正常成功路径的业务 `chat` 调用次数必须为 1；结构错误、响应截断、引用错误时保留已有项目并显示失败，用户可重试，不隐藏追加修复模型调用。

工程剧本超出可用输入／输出容量时明确报错；不静默截取开头、不假称完整覆盖、不自动拆成多轮调用。记录本次实际模型、工程剧本版本和提取合同版本，便于排查缺失。

## 4. 提取内容合同

### 4.1 角色：汇总人物资料和造型资料

人物 `description` 保存工程剧本实际交代的完整资料，可以自然分段，不限制为一句话：

- 姓名、别名、称谓、身份、阶层、年龄、性别。
- 已交代的经历、处境、动机、关系、性格、稳定行为及说话习惯。
- 固定外貌：脸型、五官、体型、肤色、身体比例及明确不随造型改变的特征。
- 固定标记：烙印、疤痕、痣、纹身等，保留原文给出的文字、颜色、位置与方向。
- 信息之间存在冲突时保留来源并指出冲突；人物单方台词中的自称、指控或传闻应注明是谁的说法，不能自动升级为事实。

每套造型 `looks[].description` 汇总该造型相关的服装、鞋履、发型及发饰、配饰、颜色、面料、剪裁、层次、磨损和修补。某项未明确时只列重要缺口，不编造年龄、发色、身高或服装。

人物固定标记和固定外貌由角色继承，不复制出多个人物。手持短刀等记录为相关道具和镜头状态；只有明确属于服饰的结构性装备才纳入造型描述。

后续提示词可以在用户已确认风格下设计未定外观；这些设计不写回成「工程剧本提取事实」。

### 4.2 多造型识别与镜头关联

- 明确换装、不同服装、具有区别的回忆／阶段造型，建立不同 `look_id`。
- 同一服装仅名称不同，应结合工程剧本依据合并；不同衣服不能仅凭「都是黑色」合并。
- 连续镜头在没有换装依据时延续既定造型。后续镜头补充同套衣服细节时汇总到这一造型。
- 换场景本身不创建新造型；时间跳跃或回忆不能无依据继承另一时段衣服。
- 可见角色只有一套未具体描述的造型时建立「未注明造型」，保留已知信息即可，不阻止提取。
- 多套造型存在、具体镜头无法确定时记录为待指定，不猜测。复用预览中的造型选择控件供用户指定，受影响的下游生成在绑定确定后执行；不要求重新分析工程剧本。
- 纯画外音／旁白按需要登记说话身份与声音资料，但不因提及人物而为当前镜头增加可见角色或参考图。
- 人物被对白提到、道具被回忆提到，不等于该资产实际入镜；`shot_bindings` 按画面需要绑定，关系信息仍可汇总进人物资料。

### 4.3 场景与道具

| 资产 | `description` 应保留的工程剧本信息 |
| --- | --- |
| 场景 | 名称／别名、时代地域、功能规模、空间边界、前中后景、入口出口、动线、地标、建筑与固定陈设、材质色彩、时间天气、明确的光源与空间关系 |
| 道具 | 名称／别名、所属或关联人物、剧情功能、形状比例、尺寸线索、结构组件、材质色彩、文字图案、固定磨损位置、使用方式及工程剧本交代的状态变化 |

镜头临时站位、拍摄角度、表情和动作仍留在工程剧本／镜头，不写成资产永久外观。场景空间结构和道具状态有依据的信息必须保存；本期不把多造型机制泛化成场景／道具的全新版本系统。

### 4.4 来源依据

角色、造型、场景、道具均可保存 `extraction_evidence`：

```text
script_id             后端填写所属集 ID
screenplay_revision   后端填写本次工程剧本版本
shot_number           来源镜头号；工程剧本总说明为 null
quote                 工程剧本中可定位的短原文
```

同一事实的重复来源可去重，但后面补充的新事实必须保留。证据中的镜头号和引用文本由本地校验，来源不成立不能当成已核实信息。跨集共享资产保存来源时带集 ID，不能把不同集的「镜头1」混为一个来源。

## 5. 数据结构与所有权

### 5.1 最小模型扩展

继续使用 `Character / Scene / Prop` 和既有 `description / extracted_description`。增加下列内容：

| 模型 | 字段与职责 |
| --- | --- |
| 三类资产 | `extraction_evidence=[]`：来源清单；`extraction_unknowns=[]`：重要未交代或冲突项 |
| `Character` | `looks: List[CharacterLook]=[]`：同一人物的造型；九维声音、身份、别名保留在人物层 |
| `CharacterLook` | `id / name / description / extracted_description / extraction_evidence / extraction_unknowns` |
| `CharacterLook` | `description_source / description_version / locked`：复用现有描述保护语义 |
| `CharacterLook` | `reference_sheet: AssetUnit`：这一造型的提示词、候选图片和已选图片；与人物顶层容器不共享可变对象 |
| `CharacterLook` | 提示词任务状态、任务号、错误和 `production_image_task`：复用现有字段约定，结果归属于明确造型 |
| `StoryboardFrame` | `character_look_ids: Dict[str, str]={}`：`character_id → look_id`；`character_ids` 继续表示镜头可见角色 |

`looks` 中的候选图片仍属于 `reference_sheet.image_variants`；不能把一套服装的多次重生成误当成多套造型。

镜头使用关系只存于当前集的帧／提取预览。共享 `CharacterLook` 不保存裸镜头号列表，以免跨集引用互相污染。提取预览可以暂存当前工程版本的 `source_shot_numbers`，采用时转为帧绑定。

### 5.3 稳定 ID、重复提取及共享资产

- 新建、复用和别名匹配沿用现有资产来源与唯一匹配规则，真实人物 ID 由后端决定。
- 同一人物、同一套造型重新提取时复用 `look_id`，不依赖数组序号或完整描述哈希来识别；描述扩充不能自动变成新造型。
- 已有唯一命中的角色不能继续直接 `continue` 跳过：应更新本集提取资料及新增造型，原位保存。
- `extracted_description` 保存最新工程版本提取结果；人工修改的 `description` 保留，新增事实和冲突可见，不覆盖人工设定。造型沿用同一规则。
- 保留已选图片、图片历史、手动提示词、角色九维声音和锁定项；没有再次出现的旧造型不自动删除，仅不进入本集生成范围。
- 有系列则按现有系列归属写回；独立项目写本集。全局资产保持只读，需要编辑时使用已有复制语义。共享人物的造型、提示词和换图影响其他使用该造型的集，按实际引用标记派生产物过期。
- 不能自动按历史 `persona` 标签合并不同 `Character.id`；该字段原有语义和歧义仍保留，自动迁移历史多人物记录不在本期范围。

## 6. 提示词、图片与声音的消费合同

角色生图输入由明确资料组装：完整人物 `description`、有效的年龄／性别字段、固定外貌与标记、当前 `look.description`、确认风格和画幅。必须包含当前造型，不能只传一句角色概述，也不能把其他衣服并入同一张参考板。

场景和道具使用其完整描述及有效结构化属性，复用现有内置 `jc-character-prompt / jc-scene-prompt / jc-prop-prompt`。本次资产提取不执行完整漫剧 Skill 集群，不增加角色环境图后再转参考板的强制双次生图。

同人物新造型生图时，复用用户已选身份图作为身份参考，并固定脸部、身体及标记；服饰以当前造型为准。按既有图像通道的参考图能力提交，能力不满足时沿用通道错误反馈，不静默更换模型或自动追加身份生成步骤。

提示词任务、生图任务、前端排队记录和 `activePolls` 需要区分 `(character_id, look_id, generation_type)`；不同造型可各自完成，A 的迟到结果不能写入 B，也不能清除 B 的加载状态。角色共用资料变化使受影响造型提示词过期，单套造型变化只影响该造型。

九维声音只存储在角色层，从完整人物资料及工程剧本明确的稳定说话习惯设计。换装不重新创建九维档案，不生成参考音频，不提交历史参考音。

## 7. 镜头、分段与真实提交的造型绑定

采用提取结果时，将 `shot_bindings` 的临时人物／造型 ID 映射为真实 ID，并按 `source_shot_number` 写入帧。每个可见人物必须属于该镜头 `character_ids`，其造型必须属于该人物。

新流程的明确绑定不能被后续按姓名扫描覆盖；旧流程继续使用原匹配行为。镜头号或帧重新同步时，按既有工程来源映射保留有效绑定，失配则提示重新提取／指定，不能把旧造型套入新镜头。

分段引用规则：

- 角色图片键为 `(character_id, look_id)`，场景和道具仍按各自资产 ID；图片编号和实际上传顺序共同从这一清单生成。
- 角色 `asset_refs` 增加 `look_id / look_name`；描述为人物固定识别信息及本套服装的简述，声音取人物的同一份九维档案。
- 同段同人物一套造型只上传一次；确实出现两套造型则分为两个图片引用，并在对应镜头写明使用关系，不能因人物 ID 相同去掉第二套衣服。
- 结尾 1 秒全景使用结尾实际在场人物及其当时造型。下一段若同场连续，继承该造型；换装依据优先于上一段继承。
- 指定造型缺图时明确显示缺失并定位到该造型，不能回退到人物的其他服装参考图。
- 造型换图、修改绑定时，刷新相关段的实际引用、段版本、提示词采用状态和待提交视频输入；已生成视频和历史快照保留。
- 创建视频任务仍验证本段当前有序引用及版本，保存 `character_id / look_id / selected_image_id` 与 URL 快照。上传的是本段选定造型图，前端标题正确不足以视为完成。

## 8. API 与界面改动

| 接口／模块 | 本期合同 |

| `POST .../production/assets/apply` | 继续校验提取任务和工程版本；采用预览中已确定绑定，原位合并 |
| 资产提示词生成／保存、图片生成、图片选择／删除／收藏／上传接口 | 角色请求支持可选 `look_id`；显式指定时严格按该造型路由，错误 ID 返回可定位错误 |
| `GET /projects/{id}` 与系列资产读取 | 返回造型列表、各造型状态及帧的 `character_look_ids`；保留现有字段 |
| 角色描述更新 | 明确区分人物资料和造型资料，版本分别维护；既有未传 `look_id` 行为保持兼容 |
| 分段规划、渲染、刷新及视频提交 | 消费帧绑定及造型图片；图片编号、版本、实际请求一致 |

角色卡仍一人一张，显示当前主展示图和「N 套造型」。工作台继续使用主参考图／描述／生图提示词三栏，在生图页增加造型切换：人物共用资料可展开编辑，当前造型的描述、提示词和候选随选择切换。切换不发起生成、不丢未保存修改；保存失败不假装成功。

声音页不随造型切换，始终对应当前人物。场景、道具保持现有工作台，描述显示完整，证据与缺口折叠显示。

提取预览保留现有确认操作，并显示人物数／造型数、场景和道具数；只在造型归属确实不明的镜头显示待指定，不增加逐条必填审核。批量生成按当前集实际引用且用户选中的造型处理；提示词／图片计数按造型，九维声音按人物去重。

## 9. 历史兼容与版本规则

历史数据缺少 `looks` 时仍可读取和展示原 `reference_sheet / full_body_asset / image_url`。读取不迁移、不写盘。新流程首次明确编辑／采用造型时，才将原有媒体和提示词归到同一个「默认造型」，保留原图片 ID、历史和选定状态；避免所有造型共享同一个候选池。

历史镜头没有 `character_look_ids` 时：仅一套可用默认造型可回退；存在多套造型且无法确定时提示指定，不任意选第一套。显式指定造型的图片读取永远不能回退到另一套造型。

提取任务保存工程剧本、设置和提取合同版本。排队或执行中源版本变化，迟到结果标为失效且不写入；继续复用现有工程有效性检查和写盘错误处理，不读取原始剧本文本来补充提取。

采用写入前完成所有结构和引用校验；失败不留下半套角色／造型／镜头绑定。复用项目、系列的严格保存及恢复机制；响应成功必须代表对应归属持久化成功。

## 12. 完成定义

用户在第三步发起一次提取，即可得到工程剧本中所有相关资产的完整已知资料；同一个人以一张人物卡管理多套造型，镜头使用正确造型，提示词和真实提交都携带完整资料与对应图片。刷新后信息、来源、造型、主图及绑定保持一致。以上验收通过后，才能标记本 TDD 已实施。
