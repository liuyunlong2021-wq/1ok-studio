# 剧本编辑器优化合同

状态：方案确认，待实施  
日期：2026-09-05

## 1. 合同目标

在不改变剧本编辑器现有数据结构、编辑能力和制作流程的前提下，完成两件事：

1. 让剧本编辑器完整接入 LumenX 全局主题，不再单独使用乌黑的旧主题。
2. 对现有按钮和入口进行可用性收口：可用功能保持可用，占位功能明确处理，不出现点击无反应的隐形按钮。

## 2. 不变项

以下内容本期不重做：

- Tiptap 编辑器和现有节点扩展。
- 剧本格式解析、粘贴格式化和自动保存。
- 场景、角色、对白、动作、镜头等数据结构。
- 左侧场景/大纲/搜索信息架构。
- 右侧角色/镜头/管线/地点/道具/笔记/AI 面板信息架构。
- Storyboard、资产库和项目制作流程。
- 现有快捷键和键盘操作。

主题迁移只改视觉 token；按钮补齐只改对应入口和状态反馈，不改变已有业务含义。

## 3. 现状基线

编辑器当前由以下区域组成：

```text
顶部格式工具栏
    -> 格式、文字渲染、撤销、重做、AI、视图切换、导出
左侧栏
    -> 场景、 大纲、搜索
中间编辑区
    -> Tiptap 剧本编辑、粘贴提示、离线恢复
右侧栏
    -> 角色、镜头、管线、地点、道具、笔记、AI 补全
底部状态栏
    -> 字数、场景数、保存状态、连贯性、当前格式
```

当前主题异常的根因是编辑器大量使用 `bg-[#050508]`、`bg-zinc-*`、`text-white`、`border-white/*` 和 `prose-invert`，绕过了全局的 `bg-surface`、`bg-elevated`、`text-foreground` 等语义变量。

## 4. 视觉统一合同

### 4.1 Token 映射

| 旧写法 | 统一写法 |
|---|---|
| `bg-[#050508]` | `bg-bg-base` 或 `bg-surface-inset` |
| `bg-zinc-900` | `bg-surface` |
| `bg-zinc-800` | `bg-elevated` |
| `bg-zinc-700` | `bg-hover-bg` 或 `bg-glass` |
| `text-white` / `text-zinc-200` | `text-foreground` |
| `text-zinc-300` | `text-text-secondary` |
| `text-zinc-400` / `text-zinc-500` | `text-text-muted` |
| `border-white/10` | `border-border-subtle` |
| `bg-indigo-*` | `bg-primary` 或 `bg-primary/15` |
| `bg-purple-*` | `bg-accent` 或状态 token |
| `prose-invert` | 主题化的 `prose` 样式，不强制反色 |

不存在完全对应的颜色时，优先使用语义 token，不新增一次性颜色。

### 4.2 统一范围

主题迁移覆盖：

- `ScriptEditorShell`
- `FormatToolbar`
- 左侧场景、大纲、搜索面板
- 右侧所有面板
- 导入、导出、快照、管线关联弹窗
- 粘贴提示、快捷键帮助、连贯性提示
- StoryboardView
- 编辑器专用输入框、下拉框和空状态

验收要求：切换任意已存在主题时，编辑器背景、面板、文字、边框、选中态和弹窗都同步变化；不得出现一块固定黑色区域。

## 5. 按钮和入口合同

### 5.1 必须保持可用

- 格式选择：切换格式并更新编辑器渲染。
- 文字渲染：切换中文/日文/拉丁渲染。
- 撤销/重做：根据历史状态正确禁用和恢复。
- 编辑/分镜/阅读/聚焦：切换对应视图。
- 左右侧栏折叠：隐藏和恢复侧栏。
- 场景点击：跳转并自动展开目标场景。
- 场景拖拽：调整场景顺序，并同步编辑器文档状态。
- 场景颜色：设置、取消并持久化颜色。
- 搜索与类型筛选：定位结果并跳转原文。
- 右侧面板切换与锁定：锁定后不被光标自动切换。
- 快照恢复和删除：操作后刷新当前编辑器状态。
- 管线关联：选择已有项目或创建项目并完成关联。
- 本地缓存恢复/关闭：恢复或明确放弃本地版本。

### 5.2 占位入口的处理

| 入口 | 当前状态 | 本期处理 |
|---|---|---|
| 顶部 AI | 禁用占位 | 保持禁用，但增加“即将支持”提示；不允许伪装成可用按钮 |
| 顶部导出 | 禁用占位 | 接通现有 ExportDialog；至少支持已有导出格式 |
| AI 补全“应用” | 当前只打印日志 | 写入编辑器或明确改名为“确认记录”；不得无反馈 |
| 空场景“添加镜头” | 已有入口 | 保持功能，补充成功后的定位反馈 |

本期不新增 AI 业务能力；只处理已有入口的真实状态。

## 6. 实施步骤

### 阶段 0：基线冻结

1. 记录当前编辑器功能、截图和主题切换结果。
2. 确认现有测试和 Tiptap 节点行为不变。
3. 建立硬编码颜色清单，作为迁移验收依据。

### 阶段 1：主题 token 迁移

1. 先改 `ScriptEditorShell` 根容器、工具栏、侧栏和状态栏。
2. 再改左右面板和所有弹窗。
3. 移除 `prose-invert` 对编辑正文的强制反色。
4. 将 indigo/purple 选中态收敛到 `primary`、`accent` 和状态 token。
5. 保持尺寸、布局、动画和信息架构不变。

### 阶段 2：交互状态收口

1. 给所有禁用按钮提供明确的 disabled 样式和 title。
2. 接通导出入口与现有导出弹窗。
3. 修复 AI 补全应用的无效点击。
4. 确认拖拽、颜色、快照、管线关联等操作有保存或反馈。
5. 统一加载中、成功、失败和空状态的主题样式。

### 阶段 3：回归验证

1. 验证四种视图切换。
2. 验证三种主题切换。
3. 验证粘贴、自动保存、离线恢复、撤销和重做。
4. 验证场景导航、搜索跳转和右侧面板自动切换。
5. 验证导入、导出、快照恢复和管线关联。
6. 验证桌面横屏和窄窗口下无内容遮挡。

## 7. 验收标准

### 视觉

- 编辑器不再出现固定 `#050508` 或大面积纯黑背景。
- 所有主题下背景、文字、边框、输入框和弹窗具有可读对比度。
- 编辑器与创作台、资产库共享同一套颜色语义。
- 不引入新的独立深色主题。

### 功能

- 已有可用按钮行为不回归。
- 禁用按钮不会出现“点击无反应”的误导体验。
- 导出按钮可以打开并完成已有导出流程。
- AI 补全应用操作有明确结果。
- 场景颜色和排序在刷新后不丢失，或明确显示为仅本地状态。

### 工程

- 不修改剧本节点协议和后端接口，除非导出或持久化修复确实需要。
- 不新增主题依赖、UI 框架或颜色体系。
- 前端 TypeScript 检查通过。
- 现有编辑器测试通过，并补充至少一条主题切换回归检查。

## 8. 交付顺序

```text
主题统一
  -> 视觉验收
  -> 导出/AI 占位入口收口
  -> 持久化与反馈验收
  -> 全量回归
  -> 提交
```

本合同完成后，剧本编辑器仍然是原来的编辑器，只是与 LumenX 主产品统一视觉，并且不再存在明显的“按钮存在但没有动作”的低级断点。

## 9. 占位功能补全合同

## 10. Skill 标准化与文档转换合同

### 10.1 Skill 选择

标准化弹窗必须同时提供文本模型和文本处理 Skill 选择器。Skill 来源分为内置 Skill、项目/系列已保存 Skill、本次上传 Skill；上传内容可编辑，可选择仅本次使用或保存到项目。当前弹窗只展示剧本标准化、剧本润色、结构检查等文本处理 Skill，不混入角色、场景、道具和分镜 Skill。

### 10.2 预览与应用

AI 返回的标准化结果先作为可编辑纯文本预览，用户确认后才写回编辑器。应用不得调用 `setContent(string)` 直接当 HTML 解析，必须经过纯文本到 Tiptap JSON 的转换层：第一版先逐行保留换行和空行，清理 Markdown 代码围栏，无法确定语义的行降级为动作节点；后续再按场景、角色、对白、动作映射到现有节点。

### 10.3 版本与失败保护

应用标准化结果前保留原文，可撤销；应用后标记未保存，保存时创建版本快照。模型调用失败、Skill 为空或返回空内容时，不修改编辑器，并在弹窗内显示原因。

本阶段针对现有界面中存在但未完整接通的功能执行以下约定。

### 9.1 顶部 AI 修改入口

顶部 AI 只保留一个直接入口，打开“AI 修改剧本”弹窗；删除 AI 下拉菜单、分析当前段落和右侧 AI 补全面板。实体提取保持原有独立流程，不混入 AI 修改。

弹窗固定保存打开时的选区：有选区时修改选中内容，无选区时修改全文。左侧待修改内容可编辑，并提供文本模型、可管理 Skill、本次修改要求；右侧结果可编辑，支持复制、重新生成和应用。应用时精准替换原选区或全文，继续使用逐行 Tiptap 文档节点，保留撤销并标记未保存。

### 9.2 导出

导出按钮使用现有 `ExportDialog`。无项目 ID 时允许 Fountain、FDX、TXT，PDF/DOCX 显示需要关联项目。导出中禁止重复点击，失败时保留弹窗和错误信息。

### 9.3 AI 补全写回

“应用”必须产生可见结果：

- 角色：更新角色索引，避免重复角色。
- 地点：更新场景地点和时间元数据。
- 道具：加入当前场景的结构化实体候选。
- 节拍：写入当前场景动作或镜头节点。

应用后保留撤销能力，并显示“已写入剧本/已确认实体”等状态；不再使用无效 `console.log`。

### 9.4 派生实体与资产库

派生实体不自动进入资产库，固定采用：

```text
剧本文本 -> 派生实体 -> 用户确认 -> 资产候选 -> 用户创建/保存资产
```

角色、地点、道具面板提供“确认实体”和“创建资产”两个不同动作。

### 9.5 场景颜色与排序

- 场景颜色当前使用本地缓存，后续升级为项目级 `scene_colors` 持久化。
- 场景拖拽必须通过 Tiptap 文档事务移动完整场景节点，不能只交换标题或停留在视觉占位。
- 移动后触发自动保存，刷新后顺序保持，撤销可恢复。

### 9.6 右侧实体面板

第一版只增加最小编辑能力：

- 角色：名称、描述、确认、创建资产。
- 地点：地点、时间、内外景、确认、创建资产。
- 道具：名称、描述、出现位置、确认、创建资产。

编辑结果必须写入编辑器节点属性或项目 API，不得只留在 React 本地状态。

### 9.7 空白剧本

编辑器无内容时显示：

```text
新建空白剧本 / 使用中文短剧模板 / 使用电影剧本模板 / 导入剧本文件
```

选择模板只写入最小示例结构，不创建资产、不触发 AI。

## 10. 执行顺序与验收

```text
AI 菜单与空状态
  -> AI 补全写回
  -> 导出状态
  -> 场景拖拽事务
  -> 实体确认与最小编辑
  -> 颜色项目持久化
  -> 全量回归
```

验收必须覆盖：AI 入口、导入导出、撤销重做、粘贴格式化、场景跳转、场景排序、实体确认、资产创建入口、空白剧本模板、主题切换、离线缓存恢复和横屏布局。

## 11. 编辑器归属与工作区融合合同

### 11.1 产品归属

剧本编辑器不再作为首页全局工具存在。剧本的唯一归属单位是“项目集（episode project）”：一个项目集对应一份独立剧本、独立编辑状态、独立实体派生结果和独立保存版本。

产品关系固定为：

```text
工作区
  -> 系列
    -> 第 1 集 / 第 2 集 / 第 3 集 / ...
      -> 当前集的完整剧本编辑器
```

首页不提供独立剧本编辑入口，也不创建没有项目归属的剧本。原首页 `#/studio/editor` 入口改为跳转到工作区或提示用户先选择系列/集。

### 11.2 单一编辑器实现

新版 `ScriptEditorShell` 是唯一正式剧本编辑器。工作区项目页的 Script 步骤直接复用它：

```tsx
<ScriptEditorShell
  key={projectId}
  mode="embedded"
  projectId={projectId}
/>
```

`key={projectId}` 用于切换集数时重新建立编辑器实例，防止上一集的 Tiptap 文档、选区、撤销栈、离线缓存和面板状态泄漏到下一集。

旧版 `ScriptProcessor` 不再作为正式入口。迁移期可以保留文件和兼容代码，但不得继续从项目页渲染；新版稳定并完成回归后再删除死代码。

### 11.3 工作区与编辑器职责

工作区负责项目/集级别的导航和制作流程：

- 系列面包屑和集数列表；
- 新建集、切换集、删除集和集状态；
- 当前集的步骤导航；
- 提取实体入口；
- 资产、分镜、动作、合成等制作阶段入口。

剧本编辑器负责当前集的文档生产：

- Tiptap 编辑和节点格式；
- 场景、大纲、搜索、角色、镜头、地点、道具、笔记面板；
- AI 修改剧本、Skill 和文本模型；
- 粘贴格式化、导入导出、快照、撤销重做；
- 自动保存、离线恢复和当前集文档状态。

同一功能不得同时在工作区和编辑器各实现一份。工作区只保留入口和状态汇总，编辑器负责文档内操作。

### 11.4 当前集数据边界

编辑器打开时必须绑定明确的 `projectId`。所有读写均以当前集为边界：

```text
/projects/{projectId}/document
/projects/{projectId}/text
/projects/{projectId}/document/snapshots
/projects/{projectId}/derive_gaps
```

保存至少同步以下内容：

- Tiptap JSON 文档；
- 当前集原始文本 `original_text`；
- 当前集派生场景、角色、道具；
- 当前集更新时间和保存状态；
- 当前集文档快照。

兼容读取 `originalText` 和 `original_text`，但写入时以现有后端字段协议为准，避免首页旧字段和工作区新字段相互覆盖。

### 11.5 多集持续创作

系统必须支持连续创建和编辑多集：

```text
新建第 1 集 -> 编辑/保存第 1 集
新建第 2 集 -> 编辑/保存第 2 集
新建第 3 集 -> 编辑/保存第 3 集
新建第 4 集 -> 编辑/保存第 4 集
```

切换集数时必须满足：

- 加载对应集的剧本文本和 Tiptap 文档；
- 加载对应集的实体派生结果；
- 加载对应集的保存状态、快照和离线缓存；
- 不显示上一集内容；
- 不覆盖上一集数据；
- 当前集修改后只标记当前集未保存。

系列可以共享项目级风格和模型默认值，但剧本文本、实体和编辑器历史不能跨集混用。

### 11.6 提取实体边界

“提取实体”继续保留在工作区项目页，由工作区触发当前集的实体解析。解析输入必须来自当前集已保存或明确确认的剧本文本。

流程固定为：

```text
当前集剧本文本
  -> 工作区提取实体
  -> 当前集角色/场景/道具候选
  -> 用户确认
  -> 资产创建或关联
```

编辑器中的角色、地点、道具面板负责展示和最小编辑，不再另起一套项目级提取流程。AI 修改剧本也不自动触发实体提取，避免一次操作同时改变文档和资产数据。

### 11.7 路由与入口迁移

迁移后的入口合同：

| 入口 | 处理 |
|---|---|
| 首页剧本编辑器 | 删除正式入口；旧 hash 跳转工作区或提示先选集 |
| 工作区系列详情 | 保留集列表和新建集 |
| 工作区项目/集 Script 步骤 | 渲染 `ScriptEditorShell mode="embedded" projectId={episodeId}` |
| 旧版 `ScriptProcessor` | 停止渲染，迁移期保留文件 |
| 提取实体 | 由工作区当前集入口触发 |

### 11.8 实施顺序

```text
1. 在 ProjectClient 的 Script 步骤接入 ScriptEditorShell
2. 以 projectId/key 隔离集切换和编辑器状态
3. 对齐 document 与 original_text 保存
4. 迁移提取实体入口到当前集数据流
5. 将首页编辑器入口改为跳转工作区
6. 停止渲染 ScriptProcessor
7. 完成多集切换、刷新、保存、恢复回归
8. 删除确认无引用的旧编辑器代码
```

### 11.9 验收标准

- 第 1 集和第 2 集可以分别创建、编辑、保存和刷新恢复；
- 在第 2 集修改文本不会改变第 1 集；
- 切换集数不会残留上一集正文、选区、撤销栈或面板数据；
- AI 修改、Skill、导入导出、快照均绑定当前集；
- 提取实体只作用于当前集；
- 首页不再出现独立的“新建空白剧本”工作流；
- 工作区只存在一套完整剧本编辑器；
- 旧版 `ScriptProcessor` 不再被项目页引用；
- 刷新页面后当前集仍能恢复正确剧本和保存状态。
