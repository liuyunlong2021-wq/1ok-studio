# 创作台音频生成接入方案

状态：方案确认，待实施  
日期：2026-09-05

## 1. 目标

在现有“创作台”中增加音频生成能力，支持文生音频和参考音生音频。创作台现有布局、颜色、卡片、按钮、参数抽屉、历史结果和交互风格全部复用，不新增独立音频工作台。

## 2. 明确不改的范围

以下模块保持现状：

- 剧本编辑器
- 提取实体逻辑
- 角色、场景、道具工作台
- 资产库分类和资产生成流程
- Storyboard 与分镜生成逻辑
- 项目主工作流和现有图像、视频模式

声音设计与导演声音稿都只是创作台里的 Prompt 模板，不做成固定业务模块，也不和角色资产、场景资产或道具资产绑定。

## 3. 创作台模式

现有模式分组保持不变，在其下方增加“声音”分组：

```text
图像：文生图、图生图
视频：文生视频、图生视频、参考生视频、视频编辑
声音：文生音频、参考音生音频
```

建议内部模式值：

```ts
type PlaygroundMode = 't2i' | 'i2i' | 't2v' | 'i2v' | 'r2v' | 'v2v' | 't2a' | 'r2a';
```

### 3.1 文生音频（t2a）

- 输入：Prompt 编辑框中的文本。
- Prompt 可以是普通声音描述，也可以是完整的导演声音稿或声音设计 Skill 内容。
- 不需要参考素材。
- 生成按钮沿用现有创作台主生成按钮。

### 3.2 参考音生音频（r2a）

- 输入：Prompt 文本 + 参考音频。
- 参考音频最多 3 段。
- 参考音频支持上传后试听、删除和重新选择。
- 参考音频仅作为本次生成输入，不自动写入资产库，也不改变角色资产。

## 4. Prompt 模板

模板抽屉的分类增加“音频”，筛选项变为：

```text
全部 / 图像 / 视频 / 音频 / 通用
```

模板仍沿用现有字段：

```ts
{
  name,
  category,
  prompt,
  negative_prompt,
  default_mode,
  default_model_id,
  default_parameters
}
```

新增模板时，用户可以：

1. 分类选择“音频”。
2. 将完整 `SKILL.md` 内容粘贴到 Prompt 中。
3. 选择默认模式“文生音频”或“参考音生音频”。
4. 选择默认模型 `seed-audio-1.0`。
5. 保存后，在 Prompt 末尾补充本次具体剧本、角色、台词或声音任务。

不硬编码“声音设计模板”和“导演声音稿模板”两种业务类型；两者由用户自己保存的 Skill 模板区分。

## 5. 参数设计

参数抽屉继续使用现有创作台组件，只展示 Seed Audio 接口真实支持的参数：

```text
模型：seed-audio-1.0
输出格式：MP3 / WAV / PCM / Opus / OGG Opus
```

规则：

- 第一版默认 MP3。
- `t2a` 不显示参考音频上传参数。
- `r2a` 显示参考音频区域和“最多 3 段”提示。
- 不增加语速、音高、音色、批量数、seed 等接口未承诺的参数。
- 音频模式隐藏负面提示词；Seed Audio 不需要负面提示词。

## 6. 韭菜盒子 API 接入

使用现有环境设置中的韭菜盒子配置，不在创作台单独保存密钥。

```text
Base URL: https://api.jiucaihezi.studio
POST /v1/audio/speech
model: seed-audio-1.0
Authorization: Bearer <JIUCAIHEZI_API_KEY>
```

请求结构：

```json
{
  "model": "seed-audio-1.0",
  "input": "文本或完整 Skill + 本次任务",
  "response_format": "mp3",
  "metadata": {
    "references": [
      { "audio_url": "..." },
      { "audio_data": "<RAW_BASE64>" }
    ]
  }
}
```

实现约束：

- `input` 长度为 1–3000 字符。
- 参考音频最多 3 段。
- 成功响应是音频二进制，不是 JSON。
- API Key 只在后端读取，不能进入前端代码、浏览器存储或日志。
- 本地上传的参考音频由后端转 Base64，或转换为服务端可访问地址。
- 后端复用现有创作台任务、鉴权、文件保存、历史记录和错误展示机制。

## 7. 结果展示

结果类型扩展为：

```ts
type MediaType = 'image' | 'video' | 'audio';
```

音频结果卡片复用现有 ResultCard 的外框、标题、状态、操作按钮和历史布局，仅替换媒体区域：

- 使用原生 `<audio controls>` 播放。
- 显示格式、时长、模型、生成模式和创建时间。
- 支持播放、下载、复制 Prompt、删除、重试。
- “作为参考音频”按钮将当前结果带入 `r2a` 模式。
- 生成失败时显示后端返回的可读原因，不清空原 Prompt 和已有结果。

结果筛选增加：

```text
全部 / 图像 / 视频 / 音频
```

## 8. 最小数据扩展

只扩展创作台通用类型，不建立新的资产域：

```ts
PlaygroundMode += 't2a' | 'r2a';
PlaygroundOutput.media_type += 'audio';
PromptTemplate.category += 'audio';
```

音频结果保存为创作台历史结果，沿用现有文件 URL、任务状态、Prompt 快照、模型 ID、参数快照和时间字段。

## 9. 生成链路

### 文生音频

```text
Prompt 模板 + 本次补充内容
        -> 创作台生成任务
        -> 后端调用 seed-audio-1.0
        -> 保存音频文件
        -> 结果卡片播放和下载
```

### 参考音生音频

```text
Prompt 模板 + 本次补充内容 + 参考音频（最多 3 段）
        -> 后端上传/转码参考音频
        -> 调用 seed-audio-1.0
        -> 保存音频文件
        -> 结果卡片播放、下载或作为下一次参考
```

## 10. 实施顺序

1. 在创作台模式类型和模式选择器中增加 `t2a`、`r2a`。
2. 在模型目录增加 `seed-audio-1.0`，并置顶韭菜盒子模型。
3. 将 Prompt 模板分类扩展为 `audio`。
4. 复用现有媒体上传组件，增加音频上传、试听和最多 3 段校验。
5. 在后端增加 `/v1/audio/speech` 的创作台分支，处理二进制响应和文件保存。
6. 扩展结果卡片、结果筛选和下载逻辑以支持音频。
7. 验证图像、视频模式以及现有模板、历史记录不受影响。

## 11. 最终边界

```text
声音能力 = 创作台的两种生成模式 + 音频 Prompt 模板 + Seed Audio 调用
```

不增加角色声音资产，不增加配音工作台，不增加全局音频时间轴，不自动切分或绑定 Storyboard。用户通过 Prompt 模板手动粘贴和维护 `jc-shengyin-sheji`、`jc-shengyin-daoyan` 等 Skill，创作台只负责统一生成、试听和管理结果。
