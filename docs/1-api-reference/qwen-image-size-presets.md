# Qwen Image 2.1 尺寸选择契约

创作台面板只选择 `resolution`（1K / 2K）和 `aspect_ratio`，不输入或提交像素尺寸。
后端根据模型目录的 `params.size.presets` 换算，在生成记录和上游请求中写入实际 `size`。
文生图与参考图编辑使用同一套映射。

| 比例 | 1K | 2K |
| --- | --- | --- |
| 1:1 | 1024x1024 | 1448x1448 |
| 16:9 | 1024x576 | 1920x1088 |
| 9:16 | 576x1024 | 1088x1920 |
| 4:3 | 1024x768 | 1664x1248 |
| 3:4 | 768x1024 | 1248x1664 |
| 3:2 | 1024x680 | 1768x1176 |
| 2:3 | 680x1024 | 1176x1768 |

2026-10-03 用户明确要求 2K + 9:16 发送 `1088x1920`，横向采用对称的 `1920x1088`。
这些尺寸均为 8 的倍数，最大边不超过 2048、总像素不超过 2,100,000，符合本机适配器限制。
尺寸约束依据：邻接 API 项目的
`docs/wiki/运维/韭菜盒子本机ComfyUI图片模型API对外接入-2026-09-26.md`。
这是本仓库的实现契约，尚未同步到共享文档归档或 Context Hub。

显式档位和比例优先于残留的 `size`；只有像素尺寸的旧历史/模板通过目录反查恢复选择。
旧 `1080x1920` / `1920x1080` 分别迁移至对应的 1088 版本。
不支持的档位或比例在创建任务前返回 HTTP 400，不提交上游生成任务。
