# 剧本修改接口的连接故障排查（2026-10-03）

## 复现和证据

使用同一把凭证、同一个 `gpt-5.6-sol` 模型和保存的剧本/上传 Skill：

- 短请求成功，证明模型和凭证可用。
- 原应用请求约 60 秒断开；自动重试后，约 126 秒返回本地 HTTP 502。
- 单次请求的底层异常是 `httpx.RemoteProtocolError: Server disconnected without sending a response.`，SDK 将它包装为 `APIConnectionError: Connection error.`。
- `urllib.request.getproxies()` 和 HTTPX 的代理映射均读取到了 macOS 系统代理 `127.0.0.1:7897`。代理运行日志确认 API 域名被转发到境外节点。
- 经这条代理路径发送同一长请求，普通请求和流式请求均约 60.5 秒断开，尚未收到接口响应。
- 显式禁用代理继承后，同一流式请求约 26.7 秒开始返回正文，94.8 秒完成，收到 `finish_reason=stop` 和约 2500 字正文。
- 仅禁用代理但仍等待一次性响应，真实应用接口在约 126 秒收到 Cloudflare HTTP 524，自动重试后约 258 秒失败。这是独立于本机代理的第二层等待限制。

这些对照定位到当前网络代理路径。尚未检查代理节点内部，无法确定具体是哪一跳关闭连接；历史 HTTP 400 的响应正文没有被旧日志保留，也不能以本次结论解释所有历史故障。

## 应用修复

`LLMAdapter` 为韭菜盒子创建专用 `DefaultHttpxClient(trust_env=False)`，明确直连网关，并流式接收正文以避免整篇生成期间没有响应。后台收齐后才将完整正文交给现有编辑器，不改变保存或接受预览的流程。缺失结束标志、输出达到 token 上限或中途断流都会报错，避免采用半篇剧本。客户端仍使用 180 秒超时，正常校验证书。修复范围是文本模型通道。

错误记录增加实际模型、耗时、上游状态码、请求 ID 和异常因果链，并遮蔽已配置的 API Key。剧本 AI 面板读取后端 `detail`，避免仅显示 Axios 的通用 502 提示。

此配置会忽略这条文本通道的系统代理、环境代理和环境中的证书设置。如果所在网络要求代理才能访问该网关，需要另行提供明确的代理配置策略。

## 验证

`python3 -m unittest discover -s tests -p test_llm_gateway_transport.py -v` 的 7 条检查通过，覆盖代理隔离、JSON 格式的完整流、无结束标志/达到长度上限/断流拒绝、历史显式 OpenAI 通道兼容、错误因果链、请求 ID 和凭证遮蔽。

前端 `npm run typecheck` 通过。

重启包含最终修复的开发版后，通过编辑器实际调用的 `POST /projects/{id}/standardize_script` 复测同一保存剧本和上传 Skill：HTTP 200，模型 `gpt-5.6-sol`，179.4 秒返回完整 2549 字正文。此次生成超过 125 秒仍完成，证明流式接收避免了原一次性响应的等待问题。验证只读取预览结果，没有将它应用或保存到用户剧本。
